## 项目概述

抖音上热门的「电子榨菜」类动物自动对战游戏。两只动物在竞技场内随机移动、撞墙弹跳、自动战斗。每种动物有符合自身特性的攻击方式和技能。用户录屏发抖音，所以对**视觉清晰度**和**随机戏剧性**要求高。

## 技术栈

- 单文件 HTML5 Canvas + 原生 JavaScript
- GitHub Pages 静态托管
- 竖屏手机适配（自适应屏幕宽度，maxW=420px, ratio=1.55）

## 设计理念

**随机性和戏剧性 > 数值平衡**。用户不是玩对战游戏——是录屏看戏。冷门翻盘、意外暴击、小鸡滚雪球才是看点。数值强者恒强反而不够"电子榨菜"。

## 当前功能 (v0.8)

- 9种动物 + 通用机制(5%暴击/远程Miss/闪避)
- 碰撞后摇(350ms) + 眩晕免疫(2500ms)，防止连到死
- 图标~2x（v0.7的3x过大挤占活动空间，回退到合理区间）
- 被动范围按体型比例，不再"全屏"
- 开局间距按最大体型自动调整，不再重叠
- 鸡3阶段蛋+4阶段生命周期(蛋→雏鸡→待出→小鸡→青年鸡→25%🐓/75%🐔)
- 移动: 直线行走，碰墙或动物碰撞后随机换方向

## 待改进

- 战斗结束后视觉效果可更丰富
- 可考虑加音效
- 可考虑加更多动物

## 版本历史

### v0.1 — 横屏原型

基础的 HTML5 Canvas 动物自动对战。两队各选一只动物，随机移动、碰撞战斗。目的是验证"自动观战"这个核心玩法是否有趣。确定了方向后就转向竖屏。

---

### v0.2 — 竖屏重写+鸡远程撒米+蛋孵化

**为什么重写**：v0.1 横屏布局不适合手机竖屏录抖音。用户的核心使用场景是手机上打开录屏→导出→发抖音。

**改动**：竖屏自适应（maxW 420）、母鸡改为远程撒米🍚（更符合"鸡"的直觉）、下蛋🥚孵化（蛋→雏鸡→青年鸡→成年帮手）、狼/蛇 DOT 改为命中触发（之前需要一直贴着才能触发，设计不合理）、暖色农场背景。

---

### v0.3 — 7项基础修复

**用户反馈（v0.2 测试后）**：
1. 地图太大 → 到死双方都没碰到
2. 小鸡不成长 → 永远是第一阶段
3. 蛋孵化太快 → 开局就三四只，狼没法打
4. 背景太混乱 → 闪烁粒子太多
5. 小鸡应该有跟随行为 → 刚孵化不该自主行动
6. 移动速度太快

**改动**：竞技场缩小（新增 arenaL/R/T/B 有效区域）、寻敌 AI（40%朝敌/30%朝中心/30%随机）、背景静态化（草丛预生成）、速度统一降低（倍率 90→50）、蛋孵化总时长 9.1s→18s、小鸡跟随母鸡（`_followOwner`）、全局数值重平衡。

---

### v0.4 — 致命Bug修复+图标放大+蛋HP系统+新被动

**致命Bug（v0.3→v0.4 最关键的修复）**：攻击距离 < 碰撞推开距离 → **所有动物永远无法近战攻击**。

- atkDist = 37px（硬编码），bodyDist = size1+size2 ≈ 45-82px
- 碰撞检测先于攻击检测，两只动物在距离 ~60px 时就被推开
- 近战触发距离 37px 永远达不到 → 只有远程能攻击 → 近战动物（熊/狼/牛/狮）完全白板
- 这就是 v0.3 用户反馈"狼多次碰撞都不攻击鸡"的根源
- 修复方式：攻击距离改为 `bodyDist + 10`（身体接触即攻击），碰撞和攻击同时触发

**调研成果**：分析 Super Auto Pets、SpaceAutoBattler、Idle Battle Sim 等成熟自动对战游戏，提取 12 条设计教训。

**其他改动**：
- 图标放大 40%（27→38 等），用户反馈图标太小看不清
- 蛋有 HP 系统（可被敌人攻击打碎），不设小鸡上限（用户明确要求），用脆弱性+长周期控制雪球
- 6 种新被动：熊狂暴/狼缠绕/鹰破盾/蛇缠绕/大象免疫/龟反伤（部分在 v0.5 被替换为更真实的机制）

---

### v0.5 — 移动AI随机化+鸡完整生命周期+通用暴击/闪避/远程Miss

**用户反馈**：
1. "所有动物往中间靠的动向太强了" — 数值强的动物聚在中间互殴，弱势的一方没有逃的空间
2. "鹰的暴击、破盾都是假的" — 没有通用暴击系统、没有通用护盾系统，鹰的被动只针对乌龟一种情况
3. "鸡不是只有两个阶段，要有完整生命周期"

**设计思路转变**：从"数值强者赢"转向"随机性和戏剧性"。电子榨菜的核心不是公平对战，而是"意料之外的翻盘"。

**根因分析**：
1. **中心偏向**：v0.3 的 AI 是 40%朝敌/30%朝中心/30%随机 → 数字上数值高的动物在中心相遇概率更高，强者恒强。修复方式：去除中心偏向，改为 30%朝敌/15%逃跑（弱势方有退路）/55%纯随机。
2. **假被动**：鹰"破盾"只在打乌龟时有意义 → 对其他 8 种动物完全是白板被动。修复方式：通用 5%暴击（所有动物）+ 鹰技能暴击 2.8x 独立判定；鹰被动改为 18% 闪避；龟"反伤"改为通用践踏；大象"免疫眩晕"保留。
3. **鸡生命周期**：用户要求鸡从蛋开始有完整成长过程。实现方式：蛋(HP=1,10s)→雏鸡(HP=5,6s)→待出(HP=8,6s)→小鸡(0阶段,不能攻击,跟妈7s)→青年鸡(远程40%Miss,7s)→50%母鸡(可下蛋)/50%公鸡(近战)。远程攻击有 Miss 概率，打偏的米粒直线飞出可能意外打中其他敌人——这是用户要的"戏剧性"。
4. **远程 Miss**：25-40% 概率打偏，米粒随机方向直线飞出，可能撞到其他敌人造成 50% 伤害——观众看到"偏了居然打到别人"会觉得有趣。

---

### v0.6 — 速度一致性+图标净化+后摇/眩晕免疫+全局重平衡

**用户反馈**：
1. 移动速度不一致，有些动物几乎静止
2. 图标旁边还有白色半透明圈没删干净
3. 牛把狼顶在角落里反复攻击，狼无法还手
4. 熊眩晕→攻击→眩晕→攻击，链式CC必死
5. "注意游戏平衡，不要只调个别动物，所有都要调整"
6. "版本号不要 *.*.**，只更新前两位"

**根因分析**：
1. **速度不一致**：倍率 50，波动 0.85-1.15 → 最慢的动物（如乌龟 speed=0.30）实际速度 = 0.30×50×0.85 = 12.75，已经肉眼不可见。修复方式：倍率 50→60，波动收窄到 0.92-1.08，同时排查 `_followOwner()`、速度 clamp、威慑逃跑三处遗漏的 `*50`。
2. **图标圈没删干净**：v0.5.1 只删了描边 stroke，但 `draw()` 中的 `ctx.arc() + ctx.fill()` 填充圆还在。修复方式：彻底移除填充圆，只保留纯 emoji。
3. **角落无限连**：碰撞推开后没有攻击冷却 → 两只动物刚分开又立刻近战触发，被顶在墙角的一方没有机会换方向就被打死。修复方式：碰撞后设置 `recoilTimer=350ms`，攻击前检查 `recoilTimer<=0`，给被顶的一方一个换方向的时间窗口。
4. **链式眩晕**：眩晕恢复后没有保护期 → 熊的眩晕拍击 CD 8s 但眩晕 1.5s，配合攻击节奏可以连续控。修复方式：眩晕恢复后 `stunImmune=2500ms`，免疫期间显示"抵抗"提示，大象显示"免疫"。
5. **全局重平衡**：ATK_CD 900→1050（降低攻击频率）、KB 4→3（减少击退幅度）、所有 9 种动物 HP/速度/伤害/技能 CD 全面微调、蛋阶段 4→3 合并（减少视觉混乱）。
6. **版本号**：从 v0.5.1 格式改为 v0.6。

### v0.7 — 图标3倍+撞墙反弹+熊冬眠修复+范围适配

**用户反馈**：
1. 撞墙不反弹，动物停在墙边
2. 熊开局原地不动
3. 图标太小，要求至少3倍
4. 大象等动物的被动范围太大，像全屏

**根因分析**：
1. **撞墙粘滞**：旧架构中 `_wallBounce()` 在速度应用**之前**检查越界。上一帧结束时 `_clampToArena` 把位置夹回边界上，下一帧 `_wallBounce` 判断"恰好在边界=未越界"→不触发反弹。动物持续往墙上走、每帧被夹回来、永远不走。修复方式：把弹墙逻辑合并到 `_clampToArena()` 中——夹边界的同时换随机方向。
2. **熊开局冬眠**：`hibernateCD` 初始值为 0，开局第一帧就满足"CD已好→冬眠"条件。冬眠期间速度每帧 ×0.9 → 几百毫秒就衰减到近乎静止，视觉上"原地不动"。修复方式：构造时检测有冬眠被动 → CD 初始化为 2-4 秒延迟。
3. **图标小**：旧尺寸 28-48px，在 ~420px 宽的手机屏幕上占比不到 10%。抖音录屏画质压缩后更看不清。修复方式：全部 ×3（鸡90 熊126 狼96 牛114 鹰90 蛇84 狮114 象144 龟90）。
4. **范围"全屏"感**：大象践踏(原35px)、狮子威慑(原75px)虽然是固定值，但竞技场只有 392px 宽，直径 70-150px 占满半屏，视觉上就是"全屏"。修复方式：范围按体型比例设定（大象践踏 160、狮子威慑 130、蛇毒溅射 100、狼独行 140），践踏的体型判断从硬编码 `size<28` 改为 `size<大象.size*0.7`。

**v0.7 引入的致命Bug（在 v0.8 修复）**：投射物碰撞判定 `dist<target.size*0.8` 中变量名写错——局部变量是 `t` 不是 `target`，导致远程攻击命中目标时抛出 ReferenceError，整个游戏循环崩溃。用户看到的症状是"按钮无反应"——实际是循环崩了画布不刷新。

---

### v0.8 — 图标回调2x+致命Bug修复+开局间距+死代码清理

**用户反馈**：
1. 图标3倍过大，两只大动物挤满竞技场没有活动空间
2. 随机和重置按钮无反应
3. 检查其他 bug

**根因分析**：
1. **3x过大**：v0.7 的 3倍放大（象144/熊126）导致两只大象体宽 288px 占竞技场(392px)的 73%，几乎开局就碰撞。修复方式：回退到 ~2x（象96 熊84 鸡60 等），两只大象占 ~49%，有充足活动空间。这个比例是：`最大体型×2 / 竞技场宽 < 50%`。
2. **按钮"无反应"**：**不是按钮代码的问题**，是 v0.7 的投射物碰撞代码 `dist<target.size*0.8` 中 `target` 应该是 `t`（ReferenceError）。当鸡等远程动物射出投射物并接近目标时，JS 抛异常 → `loop()` 崩溃 → 画布冻结。按钮的事件处理器仍然工作（`resetBattle()` 正常执行），但画布不刷新 → 用户看到"无反应"。修复方式：`target` → `t`。
3. **开局重叠**：v0.7 用固定比例（0.2/0.8）设置出生位置，大动物开局即碰撞。修复方式：`startBattle()` 根据两只动物的最大体型动态计算间距，保证出生时不重叠。
4. **死代码**：`_wallBounce()` 方法在 v0.7 已不再调用，v0.8 彻底移除。
5. **击退系数**：KB 8→5（适配 2x 尺寸，介于原始 3 和 3x 版 8 之间）。

## 设计决策记录

1. **近战=身体接触**（v0.4）：放弃"攻击距离"概念，碰撞即战斗。简单直观，不会出现"到了距离但不攻击"的 bug。
2. **碰撞驱动移动**（v0.5.1）：放弃定时换方向，改为碰墙/碰撞才换。增加不可预测性。
3. **鸡不设上限**（v0.4）：用户明确要求。但通过蛋脆弱（HP=1）、孵化长（32s）、小鸡前期不能攻击来平衡。
4. **远程 Miss 可能意外命中**（v0.5）：纯随机方向飞行的米粒可能撞到路人——这不是 bug 是 feature，用户要的"戏剧性"。
5. **版本号只留两位**（v0.6）：用户看不懂三位版本号，改为 vX.Y 格式。
6. **图标纯 emoji 无背景**（v0.6）：用户明确要求去除装饰圈，只要干净图标。
7. **冬眠初始延迟**（v0.7）：所有带 CD 的技能开局就该有随机延迟，否则 0 CD = 开局立刻触发。
8. **图标~2x**（v0.8）：3x太大(象占73%)，原版太小(占10%)，2x取中——最大两只占~50%竞技场，有充足活动空间且手机可见。判断标准：`maxSize×2 / arenaWidth < 0.5`。
9. **开局间距动态计算**（v0.8）：不再固定 0.2/0.8 比例，根据双方体型算间距，避免开局重叠碰撞。
