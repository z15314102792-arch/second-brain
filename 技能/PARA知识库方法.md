# PARA 知识库方法

> 来源：抖音「姜胡说」《AI+知识库，我的工作台长这样》+ Tiago Forte《Building a Second Brain》/《The PARA Method》（2026-08-16 调研）
> **定位：参考资料，不是当前第二大脑的目录规范。**
> 当前第二大脑的实际保存路径、目录名称与分类规则只以根目录 `CLAUDE.md` + 实际现存目录为准。未经用户明确要求重构，禁止根据本文创建 `Projects/Areas/Resources/Archives`、`01 Projects/02 Areas` 等目录。
> 适用：当用户明确讨论“是否要重构知识库/比较知识管理方法”时作为对比基准；日常保存内容不得直接按 PARA 目录落盘。

## 一、核心认知（视频第一部分）
- **Obsidian 是「看知识库的」，不是知识库本身；AI 是操作知识库的。** 库是内容，Obsidian 是界面，AI 是管家。

## 二、PARA 四类（按「可行动性」分，不按主题分）
| 类 | 含义 | 判断标准 |
|----|------|---------|
| 项目 Projects | 正在做、有目标 + 截止日期 | 「现在要交付什么」 |
| 领域 Areas | 长期维护的责任 / 兴趣（健康/财务/技能） | 「长期要维护什么」 |
| 资源 Resources | 外来的参考（书/文章/教程） | 「将来可能查什么」 |
| 归档 Archives | 暂不用、封存备查 | 「不用但别删的」 |

**流动原则**：项目完成 → 归档；项目产出 → 领域或资源；资源 / 领域里可产生新项目。信息是流动的，不是钉死的。

## 三、CODE 四步（处理一条知识的流程）
1. **捕捉 Capture**：只留真正共鸣、未来用得上、有启发的内容，不囤。
2. **组织 Organize**：按 PARA 放。
3. **提炼 Distill**：去芜存菁，笔记越提炼越精，不是越记越长。
4. **表达 Express**：重新组合成产出（文章/决策/待办）。**知识是为了用，不是存。**

## 四、姜胡说 6 目录模板（视频第二部分）
- 项目（正在做）＝ PARA 项目
- 资产（处理好的知识）＝ 内化的结论 / 规则
- 资源（外来的参考）＝ 教程 / 别人的文章
- 归档（暂时用不上）＝ PARA 归档
- 灵感库（待处理原材料）＝ 喂进来还没分类的（承接「喂内容」）
- 技能（自己的处理模板）＝ 可复用的方法模板

## 五、什么时候取出来用
- 用户明确说「想重搭/改造知识库目录」时，拿本文做**对比参考**，最终方案仍需用户确认后再修改真实目录。
- 日常“保存到第二大脑/知识库”时，**不要**用本文的「领域 Areas / 资源 Resources / 归档 Archives」直接生成路径；先按 `CLAUDE.md` 的现行分类找到已有文件。
- 处理一条知识时可以借用 CODE 的“捕捉 → 组织 → 提炼 → 表达”思路，但“组织”阶段必须映射到当前实际目录，而不是照搬 PARA 名称。
