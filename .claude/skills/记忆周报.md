# /记忆周报 — 每周知识总结

## 触发方式

用户说 `/记忆周报` 或 "本周总结" 或 "这周学到了什么"

## 执行步骤

### 第 1 步：确定时间范围

- 默认：本周一 00:00 到周日 23:59（以 `metadata.modified` 或 git log 为准）
- 用户可指定范围：`/记忆周报 上周` 或 `/记忆周报 2026-08-01 2026-08-07`

### 第 2 步：收集本周变化

通过 git log 找到本周所有 commit，提取：
1. 哪些文件被修改/新增
2. 每次 commit 的 message

### 第 3 步：提取关键事件

从 `存档/{日期}-进度.md` 和 `项目/*.md` 中提取：
1. 完成的任务（✅ 标记的）
2. 新增的项目或功能
3. 修复的 bug
4. 做出的决策
5. 踩到的坑

### 第 4 步：按项目分组

将事件按项目分组，格式：

```
## 📅 本周总结：{起始日期} ~ {结束日期}

### 🎮 中国象棋（vX.X）
- 完成了什么
- 一个关键决策：...
- 待解决：...

### 🧠 第二大脑
- ...
```

### 第 5 步：统计与洞察

```
📊 本周数字
├── 活跃项目：X 个
├── 完成任务：X 项
├── 新增项目：X 个
├── 修复 Bug：X 个
└── 做出决策：X 个

💡 本周洞察
├── 最活跃项目：xxx（X 次改动）
├── 最常遇到的问题：xxx
└── 值得关注：xxx 项目 30 天未更新
```

### 第 6 步：生成待办建议

基于本周进度，智能推荐下周优先做的事：
```
📋 建议下周关注
├── 1. xxx（因为 xxx）
├── 2. xxx
└── 3. xxx
```

## 输出

1. 保存到 `存档/周报-{结束日期}.md`
2. 更新 MEMORY.md 的存档区索引
3. 把摘要展示给用户
