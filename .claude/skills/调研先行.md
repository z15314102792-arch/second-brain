# 调研先行

## 触发条件

当用户提出以下类型的请求时自动触发：
- 推荐工具/软件/方案
- 要求实现某个功能
- 询问"能不能用 X"或"X 和 Y 哪个好"
- 涉及用户没接触过的平台或技术

## 强制规则

**第一个动作必须是搜索或检索，不是给答案。**

1. 先搜索同类方案、常见坑、最佳实践
2. 调研完再出方案，方案里写明参考了哪些资料
3. 绝对不能在调研完成前直接推荐具体工具或方案
4. 用户催促时，回复"让我先花一分钟查一下最佳方案，避免走弯路"——然后继续调研

## 反例（不允许）

- 用户问"手机怎么同步 Obsidian"→ 直接说"装 MGit"
- 用户问"坚果云能不能用"→ 直接说"可以，装一下就行"
- 用户问"Gitee 能替代 GitHub 吗"→ 直接跳到推荐其他方案

## 正例（必须这样做）

- 用户问"手机怎么同步 Obsidian"→ 先搜索 Obsidian 手机端有哪些同步方案 → 对比 → 出方案
- 用户问"坚果云能不能用"→ 先搜索坚果云做 Obsidian 同步的体验和限制 → 分析 → 给结论
