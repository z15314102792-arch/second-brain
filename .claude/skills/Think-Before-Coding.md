# Think Before Coding

> 强制需求先行协议。防止 AI 跳过理解直接写代码/出方案。

## 触发条件

接到任何需要写代码、创建文件、推荐方案的指令时自动适用。

## 协议（4 步）

### 第一步：理解需求（只读，不动手）

回答以下问题后才进入下一步：
1. 用户真正要的是什么？（用自己的话复述，不是复读指令）
2. 这个需求有哪些我可能没问但应该问的？（至少列出 1 个）
3. 用户的实际使用环境是什么？（国内/国外、手机/电脑、付费/免费、技术水平）

### 第二步：澄清歧义（问，不准假设）

- 如果一个需求有 2 种以上合理解读 → 提问确认
- 如果缺关键信息（路径、格式、范围） → 提问确认
- **铁律**：不准用假设填补信息缺口。不确定就开口问。

### 第三步：声明计划（给用户审，不动手）

说清楚：
1. 我要改/建哪些文件
2. 每个文件做什么
3. 不改什么（范围边界）
4. 有什么风险/取舍

**如果方案涉及效率质量取舍** → 必须列出选项让用户选，不能偷偷替代。

### 第四步：执行（按计划，不跑偏）

- 严格按第三步的计划执行
- 执行中发现计划有问题 → 回到第三步更新计划
- 执行中卡住 → 先调研（搜索别人怎么做的），再决定继续或换方案
