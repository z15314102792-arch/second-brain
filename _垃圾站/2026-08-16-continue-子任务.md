## Q1. DeepSeek 最新模型（deepseek-v4-pro）是否支持视觉/多模态识图？

**结论：支持情况「分渠道、且存在矛盾」——消费端（网页/App）已支持识图；官方 API 各接口支持情况不一致，Anthropic 兼容接口明确不支持图片。**

| 渠道 | 状态 | 说明 |
|---|---|---|
| **网页端 / App「识图模式」** | ✅ 已上线 | 2026-04-29 灰度，05-09 大范围开放，**06-18 正式上线**，基于一个 284B 参数多模态推理模型（"Thinking with Visual Primitives" 技术路线），可分析截图、表格、数学公式、工程图纸等。是消费端功能，**不是 API 能力**。 |
| **deepseek-v4-pro 0813 正式版（OpenAI 兼容接口）** | ⚠️ 媒体多数报道「已支持」，存在反证 | 2026-08-13 凌晨静默发布（fingerprint `fp_v4pro_20260812`，调用名仍为 `deepseek-v4-pro`）。极客公园/金融界/搜狐/今日头条等多方报道其"首次原生支持图像推理"，Fireworks AI 模型库也标注 *"Support image input"*（`image_url` 格式）。**但**微博博主"宝玉xp"称其"仍为纯文本模型，无法处理图像/视频输入"；且官方托管 API 文档的用户消息类型仍只写 `text`。 |
| **Anthropic 兼容接口 `api.deepseek.com/anthropic`** | ❌ 不支持图片 | 官方字段兼容矩阵将 `type="image"` 明确标为 **Not supported**（详见 Q2）。 |

**一句话结论**：DeepSeek 自身有视觉模型能力（网页识图模式），V4 Pro 0813 是否原生支持图片输入存疑，但**即使用户当前用的 Anthropic 兼容接口是确定不支持图片的**。

## Q2. DeepSeek 官方 Anthropic 兼容接口是否支持传图片（image 字段）？

**结论：不支持。这是本次调研最确定的结论，直接关系你的 Claude Code 配置。**

- 官方为该接口发布了**字段/内容块兼容矩阵**，`type="image"` 被明确标注为 **Not supported**（`type="document"` 同样不支持；`cache_control`、MCP 等也不支持）。
- 实际发送图片块会触发硬错误：`400 Bad Request: unsupported content type`、`InvalidRequestError` 或代理层 HTTP 422；部分情况下图片会在进入模型前被直接丢弃。
- 接口允许的内容类型仅为：`text, thinking, tool_use, tool_result, server_tool_use, web_search_tool_result`。
- 社区实测（2026-08-14）：Claude Code 接 DeepSeek 后发图片，V4-Pro 只能收到占位符 `[Image #1]` 并回复"我无法直接查看图片"。

**对你当前配置（`ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic`）的直接影响**：直接在 Claude Code 里贴图走不通，需要外部方案（见 Q4/Q4 补充）。

## 附：针对「Claude Code + DeepSeek」的落地方案建议

由于 `api.deepseek.com/anthropic` 拒绝 `image` 内容块，社区已有成熟外挂方案（均为现成开源项目，可给 Claude Code 里的 DeepSeek 加"眼睛"，原理是"眼睛=视觉模型，大脑=DeepSeek"）：

1. **deepseek-vision-gateway**（Node.js 本地网关）：含图片的请求自动转发给免费的智谱 GLM-4V-Flash 识图，转成文字后交给 DeepSeek，纯文本请求直连 DeepSeek。→ [GitHub](https://github.com/Cicicrr/deepseek-vision-gateway)
2. **deepseek-eyes**（MCP 服务器）：适配 Claude Code / Codex / Cursor，支持剪贴板、批量、多图识别，可配阿里百炼/OpenAI/智谱/Moonshot/硅基流动等。→ [GitHub](https://github.com/1235ggb/deepseek-eyes)
3. **agent-vision-mcp**：接任意 OpenAI 兼容视觉 API（Gemini/Qwen-VL/OpenAI/自托管），主模型遇到图片自动调 `analyze_image` 工具。→ [GitHub](https://github.com/kitlau86/agent-vision-mcp)
4. **glm-vision skill**：一条命令调智谱 GLM 读图，架构上"眼睛=GLM，大脑=DeepSeek"。→ 相关讨论见 [jishuzhan](https://jishuzhan.net/article/2088199871705530369)
5. 也可以**直接测试 V4 Pro 0813 的 OpenAI 兼容接口**（`api.deepseek.com/chat/completions`）是否已接受 `image_url`（多数媒体称已支持），再决定是否需要转换层。
