## 核心结论（先给答案）

你「后端 200、HTML 正常、但前端一直转圈」的现象，搜到的官方/社区资料里**最贴近**的两个根因是：**① 浏览器发起的 `/api` 请求被 Host/Origin 信任围栏打成 403**（UI 拿不到数据就一直转圈），**② 前端自身抛了 "client-side exception"**（F12 刷新可临时解决）。桌面快捷方式仍转圈，极可能因为快捷方式还是以 Edge `--app` 模式 + `127.0.0.1` 打开（这是「推测」，但跟你已确认的两个触发条件吻合）。

---

## 线索 1：`127.0.0.1` vs `localhost` 的 403 / 转圈（最对症）

- **搜到的根因**（[Discussion #900](https://github.com/deepseek-ai/deepseek-harness/discussions/900)、[Discussion #153](https://github.com/deepseek-ai/deepseek-harness/discussions/153)）：dsh 的信任围栏对 `127.0.0.1` 和 `localhost` 都放行（`isLoopbackHostname` 接受 127/8），但 `isTrustedApiRequest` 做 **Origin 与 Host 逐字符完全一致（含端口）** 的比较。当代理/VPN/浏览器扩展把 Origin 改写成无端口形式时，比较失败 → 所有 `/api/*`（如 `host.describe`、`settings.describe`）返回 403 → 页面数据加载不出 → 转圈。`localhost` 因浏览器对它的 DNS 解析（`::1`+`127.0.0.1`）和安全上下文与 IP 字面量不同，被改写的概率小，所以通常能用。
- **可操作步骤**：
  1. 访问用 `http://localhost:3080`（你已做）。
  2. **禁用改写请求地址的浏览器扩展**，或用 Edge 无痕窗口验证（#153 提到无痕正常 = 插件问题）。
  3. 用 `dsh --profile web --dump-config` 离线查看组装后的配置，确认服务侧配置没被插件改写。

## 线索 2：Edge `--app` / 桌面快捷方式仍然转圈

- **搜到的**：npm 上有专门解决这个场景的工具 [`@zhengguang-wang/dsh-desktop`](https://www.npmjs.com/package/@zhengguang-wang/dsh-desktop)（Windows 独立窗口壳）：
  - 安装：`npm install --global @zhengguang-wang/dsh-desktop`
  - 修复/重配快捷方式：`dsh-desktop install`
  - 诊断：`dsh-desktop doctor`（检查 Harness / Node / Electron / Edge 路径）
  - 它在 Electron 起不来时回退 Edge App Mode；Edge 不在标准路径时需设环境变量 `DSH_EDGE`。
- **推测（需要你验证）**：你的桌面快捷方式大概率 = `msedge.exe --app=http://127.0.0.1:3080` 或 `--app=http://localhost:3080`。`--app` 独立窗口会脱离正常标签页的 Host/Origin 上下文（且若快捷方式启动命令里先开浏览器、dsh 服务还没就绪，也会转圈）。建议：
  1. 右键快捷方式 → 目标改为 `msedge.exe --new-window http://localhost:3080`（普通标签页，去掉 `--app`）。
  2. 若快捷方式同时负责启动 dsh，改成先启动服务、等服务就绪再开浏览器，或用上面的 `dsh-desktop` 工具。
- 其他社区桌面壳（替代方案）：[chyra-moon/deepseek-harness-desktop](https://github.com/chyra-moon/deepseek-harness-desktop)、[bruc3van/dsh-desktop](https://github.com/bruc3van/dsh-desktop)、[manjiayu20071022/dsh-portable](https://github.com/manjiayu20071022/dsh-portable)（单文件 dsh.exe，双击即用）。

## 线索 3：`dsh-doctor` 诊断/恢复工具（官方问题最接近的「官方/半官方」方案）

- **搜到的**（[npmjs: dsh-doctor](https://www.npmjs.com/package/dsh-doctor)）：`dsh-doctor` v0.1.0 是 DeepSeek Harness 的确定性诊断/恢复工具，明确面向 `@deepseek-ai/dsh 0.1.0-rc.6`，**独立于 Agent 对话循环**。要求 Node 24 和 pnpm。
- **安装到 web profile**：
  ```
  dsh plugin --profile web add dsh-doctor
  dsh --profile web
  ```
  会往侧边栏加一个 Doctor 按钮 + 输入框上方的自动恢复横幅 + Settings 里的 Doctor 页面。
- **Web UI 起不来时用 CLI 恢复**：
  ```
  npx dsh-doctor recover --profile web
  npx dsh-doctor scan --profile web --json   # 诊断
  npx dsh-doctor recover --profile web --yes # 批准可逆依赖修复
  npx dsh-doctor rollback <checkpoint-id>    # 回滚
  ```
- **它能检查**：Node/平台/版本、profile 清单与 bundle 结构、YAML/JSON 语法与权限、缺失依赖、重复 bundle、损坏的 profile 链接、Cordis 插件运行阶段、最近 fatal/plugin-failure 日志、非官方插件源、模型可用性。
- **安全机制**：每次修复先建检查点（存 `$DSH_HOME/doctor/checkpoints/`，每 profile 保留 5 份），验证失败自动回滚；**绝不打印/修改/上传 API Key**。

## 线索 4：`Application error: client-side exception`（F12 刷新）

- **搜到的**（[locdd.com/t/topic/80393](https://locdd.com/t/topic/80393)）：打开 dsh 页面报 "Application error: a client-side exception has occurred (see the browser console for more information)" 的**临时解法就是按 F12 打开开发者工具再刷新页面**，能加载成功——这是浏览器端运行时问题，不是后端挂了。
- **搜到的相关根因**（[Discussion #535](https://github.com/deepseek-ai/deepseek-harness/discussions/535)）：Windows 上 `npx` 缓存里 sharp / node-pty 等原生模块下载不完整会导致前端加载失败。修法：
  ```
  rm -rf ~/.npm/_npx            # 清 npx 缓存
  npm install --os=win32 --cpu=x64 sharp   # 装 Windows 版原生模块
  node -v                       # 确认 >= ^22.19 || >=24
  ```
  并且**别用 pnpm 全局装 dsh**（dsh 是动态裸 import，读不到 pnpm 隔离结构），用 `npm install @deepseek-ai/dsh -g`。

## 线索 5：官方有没有「清缓存 / 重初始化 profile / 删 storage 文件」的建议

- **搜到的**：
  - 数据都在 `$DSH_HOME`（默认 `~/.dsh/`），首次运行生成 `profiles/`、`skills/`、`storages/`。web profile 在 `~/.dsh/profiles/web/`，含 `package.json`（profile 清单）和 `cordis.patch.yml`（用户 patch 层）。
  - **损坏的 `cordis.patch.yml` 会让 dsh 完全起不来**（提及 issues #297/#447/#708）→ 修法：删掉/修正该文件里出错的几行，或恢复备份。
  - **profile 目录删掉后重启会自动重新初始化**（web profile 首次使用会从自带模板初始化 base + web-app 两个 bundle）；但非默认 profile 缺失会报错，提示你 `dsh plugin --profile <name> add <package>`。
  - **强制杀进程**（force-kill）会导致会话 write-behind 缓冲（约 200ms 批量写盘）里未落盘的数据永久丢失，重启后历史缺失/界面像卡住（[Discussion #483](https://github.com/deepseek-ai/deepseek-harness/discussions/483)）——所以平时用正常方式退出，别强杀。
  - **浏览器缓存层面**：没有搜到 dsh 官方关于「清浏览器缓存 / Ctrl+F5」的专门说明（FAQ 只说这类异常大概率是 RC 已知缺陷，等官方修或找社区补丁）。
- **推测**：针对「双击快捷方式仍转圈」，可以试试 **Ctrl+F5 硬刷新**或清除该站点（localhost:3080）的站点数据，排除浏览器缓存的旧版 JS 产物（Vite 产物 hash 变了但 index.html 缓存了旧引用）。

## 线索 6：插件版本混装导致「Failed to load plugins / waiting for service」

- **搜到的**（[dsh-handbook FAQ](https://github.com/Electricitysheep/dsh-handbook/blob/main/docs/faq.md)）：`npx` 默认装的 CLI 可能是 `next`（rc.2），而 `dsh plugin add` 默认装 `latest`（rc.1）；混装时 rc.2 独有的 client 条目在等 rc.2 才有的服务，页面报 "Failed to load plugins … waiting for service"——**这正是「页面转圈、需要刷新」的典型原因**。修法：用 `npx -p @deepseek-ai/dsh@0.0.1-rc.1` 对齐版本，或全部升级到 `next`；当前建议插件线用 `^0.1.0-rc.6`。
- 另外**重复安装 `@deepseek-ai/dsh-tools`**（全局和 profile 各一份）会导致 "scheduler not found"，也要清掉重复依赖。

## 线索 7（补充，较冷门）：Vite SPA 根路径 / 非安全上下文

- **搜到的**（[fnOS 启动器](https://github.com/techysy/deepseek-harness-fnos)、[cnblogs 局域网访问](https://www.cnblogs.com/kongxiaoan/articles/22460353)、[dsh-lan-access](https://github.com/Leon0555/dsh-lan-access)）：Web UI 是 Vite SPA，用根绝对路径（`/assets/...`、`/api/...`）。若经网关子路径访问且没做 URL 重写，资源/API 全 404 → UI 挂。你本地直连 localhost 不涉及，可跳过。**非安全上下文**（局域网明文 HTTP）下浏览器不暴露 `crypto.randomUUID`，会导致 RPC 全挂、项目/会话列表加载不出（转圈/白屏）；`dsh-lan-access` 插件会注入 polyfill。localhost 属于安全上下文，同样不涉及。

## 给你当前情况的操作清单（按优先级）

1. **修桌面快捷方式**（最可能的残留根因）：把目标改成普通标签页 + localhost——`msedge.exe --new-window http://localhost:3080`（去掉 `--app` 和 `127.0.0.1`）。若快捷方式要顺便启动 dsh，改成先起服务再开浏览器；或直接装 `@zhengguang-wang/dsh-desktop` 省事。
2. **在仍转圈的标签页按 F12**，看 Console 里是 403、还是 "waiting for service"、还是 "client-side exception"，据此对应上面线索 1/6/4；F12 后刷新（或 Ctrl+F5）通常能进。
3. **禁用浏览器扩展 / 用无痕窗口**验证是否扩展改写 Origin 导致 403。
4. 若反复出现：`npx dsh-doctor scan --profile web --json` → `npx dsh-doctor recover --profile web`。
5. 仍不行再查：`node -v` 是否 `^22.19 || >=24`；清 `~/.npm/_npx` 重装；`~/.dsh/profiles/web/cordis.patch.yml` 是否有坏行；插件是否 rc.1/rc.2 混装；有没有重复 `@deepseek-ai/dsh-tools`。

**没有搜到** dsh 官方对「双击快捷方式仍转圈」的直接修复说明——这块主要靠上面线索 2（改快捷方式/dsh-desktop）解决，属于「推测 + 社区方案」的合成。官方明确认可的两条是：用 `localhost` 而非 `127.0.0.1`、以及 `dsh-doctor recover`。
