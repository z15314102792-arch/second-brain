# DeepSeek Harness（dsh）「一切皆插件」调研报告

> 调研日期：2026-08-15 · 覆盖：官方 GitHub 仓库、官方架构文档、CLI 参考文档、插件生态新闻、MCP 官方与社区资料

## 〇、一句话结论

**「一切皆插件」就是：dsh 这个软件本身是个空壳，所有功能（模型接入、工具、网页界面、MCP、文件操作……连命令行模式本身）都是一个个可以插拔的「插件」拼装起来的。对你这个普通用户意味着：你永远不需要「等官方加功能」——任何新能力都能像装 App 一样装进来，但坏处是目前一切都很早期、处处要动手。**

仓库地址确认：官方仓库是 **`github.com/deepseek-ai/deepseek-harness`**（不是 `deepseek-ai/dsh`，`dsh` 只是命令行名字）。npm 包名 `@deepseek-ai/dsh` 正确。来源：[GitHub README](https://github.com/deepseek-ai/deepseek-harness/blob/master/README.zh.md)、[npm](https://www.npmjs.com/package/@deepseek-ai/dsh)。

## 一、「一切皆插件」到底什么意思

### 通俗版解释
把 dsh 想成一个「空插座板」：插座板本身几乎没有功能，你插上什么就用什么。插上「网页界面」插件就有了网页版，插上「文件操作」插件就能读写文件，插上「接外部工具」插件就能连 MCP。**连「你输入一句话它去干活」这个核心循环，本身也是一个插件。** 把全部插件拔光，dsh 什么都不剩。

### 技术细节（供参考）
- 底层基于 **Cordis 框架**——这是 Koishi 聊天机器人团队做了 4 年的插件内核，只有约 2000 行 TypeScript，专职「加载插件、卸载插件、处理插件之间的依赖关系」。来源：[Cordis 插件框架解析](https://floatboat.ai/blog/cordis-plugin-framework)、[Koishi 论坛](https://forum.koishi.xyz/t/topic/3246/2)
- **一个「插件」具体指什么**：绝大多数是 **npm 包**（`@deepseek-ai/dsh-xxx` 或社区 `dsh-plugin-xxx`），包里是一个导出 `apply` 函数的小模块；装好后还要在**配置文件的一行里声明挂载**（`cordis.yml` / `cordis.patch.yml` 里的一行）。插件之间靠「依赖注入」协作：一个插件声明"我需要 tools 服务"，Cordis 会自动等提供该服务的插件先启动。来源：[官方架构文档](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.zh.md)、[插件开发实战](https://jishuzhan.net/article/2088209742899331074)
- **默认部署里有 159 个插件**，每个都能单独开/关。来源：[官方架构文档](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.zh.md)
- **热插拔**：运行时卸载一个插件，它的副作用会被自动撤销，依赖它的插件自动停用再恢复，无需重启。来源：[Cordis 插件框架解析](https://floatboat.ai/blog/cordis-plugin-framework)

### 「组装」的分层机制（你只需要知道大概）
- **Profile（档案）**：一份「用哪些插件」的配方。内置两个：`web`（网页版）和 `headless`（一次性命令行干活）。
- **Bundle（打包）**：一组插件+配置的打包，例如 `dsh-base`（基础层）、`dsh-web-app`（网页界面层）、`dsh-headless`（命令行层）。
- **Patch（补丁）**：一层层覆盖配置，后面的覆盖前面的。
- 你装的第三方插件会追加进 `~/.dsh/profiles/<名字>/` 目录下的配方里。来源：[CLI 参考文档](https://github.com/deepseek-ai/DeepSeek-Harness/blob/master/apps/cli/reference/README.md)、[官方架构文档](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.zh.md)

## 二、dsh 内置了哪些插件/能力

官方开箱即带（不装第三方就有）：

| 能力 | 说明 |
|---|---|
| **基础层 dsh-base** | 模型接入适配、工具注册、数据持久化、**沙箱与审批策略**（危险操作要你批准）、设置、凭据、遥测。每个档案都带这一层。来源：[dsh-base 说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.zh.md) |
| **Web UI（dsh-web-app）** | 你正在用的 `localhost:3080` 网页版。来源：[README](https://github.com/deepseek-ai/deepseek-harness/blob/master/README.zh.md) |
| **headless 命令行模式** | `dsh --profile headless "任务"` 一次性跑完打印答案退出，不带服务器。来源：[CLI 参考文档](https://github.com/deepseek-ai/DeepSeek-Harness/blob/master/apps/cli/reference/README.md) |
| **标准 Agent 能力（预设）** | 完整编码 Agent：文件编辑、Shell 命令、文件/网页检索、Skills（技能）、计划、目标、子代理、工作流。另有极简模式、PTC 模式（TS 编程组装多步操作）、创造模式（自定义）。来源：[dsh-web-app README](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/bundle/web-app/README.md) |
| **文件系统 + 子进程** | 读写文件、跑命令，底层可以一起切换到远程沙箱。来源：[官方架构文档](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.zh.md) |
| **MCP 客户端（内置但不默认启用）** | 官方 MCP 连接插件 `@deepseek-ai/dsh-mcp-client` 已随包附带，但默认不开任何外部 MCP 服务器（安全考虑，见问题四）。来源：[CLI 参考文档](https://github.com/deepseek-ai/DeepSeek-Harness/blob/master/apps/cli/reference/README.md) |
| **浏览器自动化** | ⚠️ **官方没有内置**。浏览器能力目前是**社区插件**（`dsh-browser` 系列），需要自己装。来源：[@anweat/dsh-browser](https://github.com/anweat/dsh-browser)、[Lum1104/dsh-browser](https://github.com/Lum1104/dsh-browser/blob/main/README.zh.md) |

## 三、第三方插件生态：有，而且已经相当活跃

**有插件生态，可以装第三方插件。** 确认信息：

- **命名与发现约定**：npm 包名约定为 `dsh-plugin-*`；GitHub 上打 `dsh-plugin` 话题标签的仓库已有 **1700+** 个。来源：[awesome-dsh-plugin](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin/blob/main/README.md)
- **精选清单（社区维护）**：`awesome-dsh-plugin`、`awesome-deepseek-harness` 两个列表收录了各分类插件。来源：[awesome-dsh-plugin](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin/blob/main/README.md)、[awesome-deepseek-harness](https://github.com/0xsline/awesome-deepseek-harness/blob/main/README.zh-CN.md)
- **插件市场**：官方在 Web UI 里提供「Plugin Market」入口（数据源为社区 registry，收录 230+ 插件）；另有多个社区市场插件（`dsh-market`、`dsh-web-plugin-manager`、`zat-dsh-engine`、`dsh-plugin-hub` 等），可在 Web UI 里浏览、搜索、一键安装。来源：[dsh-market](https://github.com/dsh-market/dsh-market/blob/main/README.md)、[dsh-web-plugin-manager](https://github.com/LX2000WASD/dsh-web-plugin-manager)
- **官方态度**：官方首发公告明确「诚邀全球开发者共建 DSH 插件生态」，并把插件机制作为长期路线（放弃为每个场景做独立 App，改走「基座+插件」）。来源：[36氪报道](https://www.36kr.com/p/3938566998834308)、[21财经](https://m.21jingji.com/article/20260814/herald/e4014aa6a2a901c1455f7147bae63b26_zaker.html)

### 安装命令（具体）
```bash
# 从 npm 安装
dsh plugin --profile web add 插件包名

# 从 GitHub 仓库安装
dsh plugin --profile web add github:用户名/仓库名

# 从本地路径安装
dsh plugin --profile web add ./插件文件夹
```
安装后通常**重启 dsh**（Web UI 会重新加载）再在设置里启用。来源：[CLI 参考文档](https://github.com/deepseek-ai/DeepSeek-Harness/blob/master/apps/cli/reference/README.md)、[插件发布文档](https://github.com/deepseek-ai/deepseek-harness/blob/HEAD/docs/user/develop/basic/publish.md)

⚠️ 注意：这台机器**没有 git、GitHub 国内可能慢**，装 GitHub 仓库的插件可能失败或很慢。优先选已发布到 npm 的插件（走 npmmirror 国内镜像更快，见问题四）。

## 四、MCP 支持：支持，而且是官方一等公民

**确认支持 MCP（Model Context Protocol，一种给 AI 接外部工具的通用「插头」协议）。**

- 官方插件 **`@deepseek-ai/dsh-mcp-client`** 负责连接外部 MCP 服务器，支持 `stdio`（本地程序）和 `streamable-http`（网络）两种方式；接进来的工具会自动出现在对话里，命名格式 `mcp__服务器名__工具名`，和 Claude Code 一致。来源：[官方 mcp-client README](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/mcp/mcp-client/README.zh.md)
- **默认不启用任何 MCP 服务器**——因为每个 MCP 服务器是"可信代码"，官方不开箱帮你连，需在配置文件 `cordis.patch.yml` 里手动加一行启用（见下面示例）。来源：[CLI 参考文档](https://github.com/deepseek-ai/DeepSeek-Harness/blob/master/apps/cli/reference/README.md)
- 配置示例（往 `~/.dsh/profiles/web/cordis.patch.yml` 加）：
  ```yaml
  - id: mcp-github
    name: '@deepseek-ai/dsh-mcp-client'
    config:
      serverName: github
      transport: stdio
      command: npx
      args: ['-y', '@modelcontextprotocol/server-github']
  ```
  来源：[官方 mcp-client README](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/mcp/mcp-client/README.zh.md)

### 免费、国内能用的 MCP 服务器推荐（官方参考服务器，无需 API Key）
| 服务器 | 干什么 | 怎么跑 |
|---|---|---|
| **Filesystem** | 安全读写文件 | `npx -y @modelcontextprotocol/server-filesystem <允许的目录>` |
| **Fetch** | 把网页抓成文字给 AI 读 | `uvx mcp-server-fetch` |
| **Git** | 操作 git 仓库 | `uvx mcp-server-git --repository <路径>` |
| **Memory** | 给 AI 一个长期记忆 | `npx -y @modelcontextprotocol/server-memory` |
| **Sequential Thinking** | 帮 AI 一步步推理 | `npx -y @modelcontextprotocol/server-sequential-thinking` |
| **Playwright / Chrome DevTools** | 浏览器自动化 | 无需 key |

来源：[MCP 官方参考服务器](https://mcp.zhcndoc.com/examples)、[2026 最佳免费 MCP 服务器](https://www.remoteopenclaw.com/blog/best-free-mcp-servers)

⚠️ **国内网络要点**：先给 npm 设国内镜像，否则装 MCP 服务器会超时：
```bash
npm config set registry https://registry.npmmirror.com
```
另外有专门给国内环境的 MCP 资源集（`awesome-mcp-zh`），预配了阿里/清华镜像、支持飞书/钉钉/企业微信/高德等国内服务。来源：[awesome-mcp-zh](https://agentindex.app/tool/awesome-mcp-zh/)

## 五、对这位用户（小白 + 国内 + Web UI/CLI）：现在 vs 未来

### ✅ 现在就能用（装好就能用，无需额外折腾）
1. **标准 Agent 干活**：Web UI 里让它读文件、改文件、跑命令、搜索、规划多步任务、派子代理。
2. **headless 命令行**：`dsh --profile headless "任务"` 一键跑完拿结果。
3. **接官方免费 MCP 服务器**：Filesystem、Fetch、Memory 等（需手动在配置文件加一行，或用社区市场插件辅助）。
4. **装社区插件**：通过 `dsh plugin --profile web add 包名` 或 Web UI 里的插件市场，比如浏览器自动化 `dsh-browser`、记忆插件、调度任务等。
5. **换模型**：dsh-base 的模型适配层可换不同的 DeepSeek 模型。

### 🔮 未来能期待（目前还没到）
1. **正式版稳定性**：现在是 **v0.1 开发者预览版**，官方明确警告「会有破坏性变更」，接口未稳定。来源：[版本阶段报道](https://jishuzhan.net/article/2088491964093054977)
2. **插件生态成熟**：官方号召共建，市场还在早期（社区市场插件居多，官方只有入口），未来会有更多像 VS Code 插件市场那样的成熟体验。
3. **IDE 连接等特化能力**：官方已明确这些将**以插件形式**出现，而非独立产品。来源：[80aj 报道](https://www.80aj.com/2026/08/14/deepseek-harness-preview-plugins/)
4. **浏览器、桌面端等**：目前都是社区做（如 Windows 桌面客户端 [Deepseek-Harness-EAC](https://github.com/zouyuxuan122/Deepseek-Harness-EAC)），官方未内置。

### ⚠️ 两点提醒（针对这位用户）
- **别急着重装/折腾插件**：版本是预览版，功能会变。想稳定用，先靠内置能力；折腾插件可以但要有「改坏了删配置重来」的心理准备。
- **国内网络**：GitHub 可能慢，尽量用 npm 镜像（npmmirror）装插件，避免装 GitHub 直连的插件。

# 给小白的一页纸总结

**「插件」对我这个普通用户来说，到底是个啥？**

你可以把 dsh 想成一个 **「装了智能引擎的 App 商城」**。dsh 自己只有个骨架，真正干活的功能全是「插件」——就像手机上的 App。现在自带了几件「App」：网页版界面、命令行干活、读写文件、跑命令、让它规划任务。想要更多功能（比如让 AI 帮你操作浏览器、给你长期记忆、接外部服务），不用等官方出，直接「装插件」就行。

**我能得到什么好处？**

1. **功能不用等**：官方没做的，社区已经做了（浏览器、记忆、定时任务、管理面板……网上有 1700 多个插件仓库，npm 上能搜 `dsh-plugin`）。
2. **可以接 MCP**：等于给 AI 装「万能外接设备」，官方有免费的 Filesystem（读写你电脑文件）、Fetch（读网页）等，接上后 AI 就能用这些能力。
3. **一个壳，随意组合**：你不喜欢哪个功能，关掉就行，不会影响别的。

**我要不要现在就去折腾？**

- **想图省心**：**先别折腾**。你现在的 Web UI + 命令行已经够日常用了。现在的版本是「公测预览版」，官方自己都说功能会变、可能不兼容，现在折腾插件容易白折腾。
- **想尝鲜**：可以试两件**风险最低**的事：① 在 npm 装个社区插件（比如装国内镜像后 `dsh plugin --profile web add 包名`）；② 接个免费 MCP（Filesystem 最安全，只让它读你指定的文件夹）。别碰 GitHub 直连的插件（国内网络容易卡）。
- **一句话决策**：**「现在先用着内置功能，等正式版稳定了再玩插件」——对你最省心、最不浪费感情。** 如果你就是想看看新玩具，从「装浏览器插件」或「接 Filesystem MCP」开始，是最有成就感又最不容易出事的两个入口。
