## 一、「一切皆插件」到底什么意思

### 通俗版解释
把 dsh 想成一个「空插座板」：插座板本身几乎没有功能，你插上什么就用什么。插上「网页界面」插件就有了网页版，插上「文件操作」插件就能读写文件，插上「接外部工具」插件就能连 MCP。**连「你输入一句话它去干活」这个核心循环，本身也是一个插件。** 把全部插件拔光，dsh 什么都不剩。

### 技术细节（供参考）
- 底层基于 **Cordis 框架**——这是 Koishi 聊天机器人团队做了 4 年的插件内核，只有约 2000 行 TypeScript，专职「加载插件、卸载插件、处理插件之间的依赖关系」。来源：[Cordis 插件框架解析](https://floatboat.ai/blog/cordis-plugin-framework)、[Koishi 论坛](https://forum.koishi.xyz/t/topic/3246/2)
- **一个「插件」具体指什么**：绝大多数是 **npm 包**（`@deepseek-ai/dsh-xxx` 或社区 `dsh-plugin-xxx`），包里是一个导出 `apply` 函数的小模块；装好后还要在**配置文件的一行里声明挂载**（`cordis.yml` / `cordis.patch.yml` 里的一行）。插件之间靠「依赖注入」协作：一个插件声明"我需要 tools 服务"，Cordis 会自动等提供该服务的插件先启动。来源：[官方架构文档](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.zh.md)、[插件开发实战](https://jishuzhan.net/article/2088209742899331074)
- **默认部署里有 159 个插件**，每个都能单独开/关。来源：[官方架构文档](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.zh.md)
- **热插拔**：运行时卸载一个插件，它的副作用会被自动撤销，依赖它的插件自动停用再恢复，无需重启。来源：[Cordis 插件框架解析](https://floatboat.ai/blog/cordis-plugin-framework)

### 「组装」的分层机制（你只需要知道大概）
- **Profile（档案）**：一份「用哪些插件」的配方。内置两个：`web`（网页版）和 `headless`（一次性命令行干活）。
- **Bundle（打包）**：一组插件+配置的打包，例如 `dsh-base`（基础层）、`dsh-web-app`（网页界面层）、`dsh-headless`（命令行层）。
- **Patch（补丁）**：一层层覆盖配置，后面的覆盖前面的。
- 你装的第三方插件会追加进 `~/.dsh/profiles/&lt;名字&gt;/` 目录下的配方里。来源：[CLI 参考文档](https://github.com/deepseek-ai/DeepSeek-Harness/blob/master/apps/cli/reference/README.md)、[官方架构文档](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.zh.md)

## 四、MCP 支持：支持，而且是官方一等公民

**确认支持 MCP（Model Context Protocol，一种给 AI 接外部工具的通用「插头」协议）。**

- 官方插件 **`@deepseek-ai/dsh-mcp-client`** 负责连接外部 MCP 服务器，支持 `stdio`（本地程序）和 `streamable-http`（网络）两种方式；接进来的工具会自动出现在对话里，命名格式 `mcp__服务器名__工具名`，和 Claude Code 一致。来源：[官方 mcp-client README](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/mcp/mcp-client/README.zh.md)
- **默认不启用任何 MCP 服务器**——因为每个 MCP 服务器是"可信代码"，官方不开箱帮你连，需在配置文件 `cordis.patch.yml` 里手动加一行启用（见下面示例）。来源：[CLI 参考文档](https://github.com/deepseek-ai/DeepSeek-Harness/blob/master/apps/cli/reference/README.md)
- 配置示例（往 `~/.dsh/profiles/web/cordis.patch.yml` 加）：
  ```yaml
  - id: mcp-github
    name: '@deepseek-ai/dsh-mcp-client'
    config:
      serverName: github
      transport: stdio
      command: npx
      args: ['-y', '@modelcontextprotocol/server-github']
  ```
  来源：[官方 mcp-client README](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/mcp/mcp-client/README.zh.md)

# DeepSeek Harness（dsh）插件生态调研报告

## 一、先给结论（一页纸）

1. **官方没有「内置长期记忆」**。dsh 官方把「记忆」定义为**会话日志本身**（事件日志，每轮对话、工具调用、推理过程都存成日志），官方刻意不做 MEMORY.md/USER.md 那种跨会话记忆文件。你要的「跨会话记忆 + 读写外部 markdown」全得靠**社区插件**。
2. **记忆插件里最值得装的是 `dsh-persona-memory`**：它把记忆存成两个可读的 markdown 文件（MEMORY.md / USER.md），并且磁盘格式与另一个 AI 助手 **Pi（Hermes Agent 生态）字节级兼容**——如果你打算让 dsh 和 Pi 用同一套记忆文件，这个插件直接命中。npm 可装，国内直连。
3. **想读写「你自己的 Obsidian 笔记」**：目前没有「一键双向同步」的现成插件。最接近的是 **KnowLP-RAG**（把 Obsidian/任意 markdown 文件夹当知识库，AI 可检索引用，以「读」为主）和官方 `@deepseek-ai/dsh-skill-filesystem`（把外部 markdown 目录当「技能」加载）。**「让 dsh 自动往你的 Obsidian 里写记忆」是市场空白，属于值得做的新插件方向。**
4. **官方 Memory MCP（`@modelcontextprotocol/server-memory`）能接**，但它的记忆存成 **JSONL 知识图谱**（实体/关系/观察），**不是 markdown，也不能指向你已有的笔记目录**。想当「共享 markdown 记忆」用它不合适。
5. **浏览器自动化插件是干嘛的**：让 AI 像人一样打开网页、看内容、点击按钮、填表、抓数据、截图（比如「帮我把这个网页商品价格抓下来存成表格」）。装它需要下载一个浏览器内核（约 400MB，国内可能慢），或复用你电脑上已装的 Edge/Chrome。
6. **给小白的第一建议**：先装 **`dshmarket`**（官方插件市场，装完 Web UI 里出现「Settings → Plugin Market」，之后所有插件都能在里面一键装），再装 **`dsh-persona-memory`** 解决记忆。浏览器插件当第二兴趣装一个试试。

## 二、A. 记忆 / 共享记忆能力（重点）

### A1. 官方内置记忆是什么形态？

- **没有独立的长期记忆系统**。官方仓库讨论 #525 明确：官方刻意**不构建** MEMORY.md/USER.md 这类文件式记忆机制，认为「会话状态就该留在会话日志里」，技能由用户自己编写审核。曾有人把 hermes-agent 的记忆机制移植成插件（`@hyls9527/dsh-memory`），仓库现已**归档停止维护**，作者结论是官方不打算内置。
- 官方文档 `docs/subsystems/session.md`：**会话日志是真源（source of truth）**。所有模型调用、工具执行、fork/resume、压缩、持久化都以「事件日志」形式留存，通过 `deriveMessages()` 派生模型每次看到的上下文。
- 第三方 `dsh-native-memory` 用 DSH 自己的存储域（`~/.dsh/storages/dsh_memory.json`）做**按工作区**的长期记忆，写入需人工审批、有来源溯源——可视为「准官方」风格的记忆插件（但仍是社区插件）。
- 结论：**官方能保证的是「跨会话续聊」（会话日志可 resume），不能保证「AI 自动记住你的偏好」**，后者必须装插件。

## 七、F. 给小白的一页纸建议

**现在最值得装这 1–2 个：**

1. **先装 `dshmarket`**（插件市场）——命令：`dsh plugin --profile web add dshmarket`，装完重启 `dsh web`，进「设置 → 插件市场」，以后所有插件点一下就能装。
2. **再装 `dsh-persona-memory`**（记忆）——命令：`dsh plugin --profile web add dsh-persona-memory`。装完它会在每次对话开头自动把记住的「你的偏好 + AI 自己的笔记」读进来，跨会话有效；记忆文件就是 `~/.dsh/memory/MEMORY.md` 和 `USER.md`，你能直接用记事本打开看/改。

**动手前务必检查两件事（否则装了没反应）：**
- **要能敲 `pnpm --version`**：`dsh plugin` 命令内部调用 pnpm。没有就先装：`npm i -g pnpm`（npmmirror 加速）。dshmarket 装好后它能帮你检测/一键配 pnpm。
- **确认 Node 版本 `^22.19` 或 `&gt;=24`**（`node --version`）。装 `dsh-mneme` 需要 Node 24+。
- **让 pnpm 也走国内镜像**：执行 `pnpm config set registry https://registry.npmmirror.com`（否则 pnpm 默认连 npmjs 官方源，国内慢）。npm 包（dshmarket、dsh-persona-memory 等）npmmirror 都有同步，✅ 国内直连；标 ⚠️ 的 GitHub 源插件会卡，建议优先选 npm 版。

**风险是什么：**
- **记忆**：AI 写的记忆偶尔会记错/记过头，插件大多有「写前扫描、字符上限、可人工改文件」保护；定期看看 MEMORY.md 就行。
- **浏览器**：让 AI 操作真实网页有误操作风险（点错按钮、提交表单），只用在你信任的网站；别让它碰付款/删除类操作。
- **插件生态**：dsh 是 0.1.0-rc.6 开发者预览版，插件兼容性随版本可能变动，装前看插件说明的适配版本。
