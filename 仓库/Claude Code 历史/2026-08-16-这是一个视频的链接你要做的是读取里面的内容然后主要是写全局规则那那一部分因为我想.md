## 关于"我不发消息你能否主动找我"

分两种情况，机制是这样的：

- **会话还开着、后台有任务在跑时**——能。比如现在这个调研子代理在后台跑，它一跑完，系统会"敲"我一下，我就会被唤醒，**不用你说话我就能把结果接着写出来给你**。这就是你现在问的场景，答案是能。
- **会话彻底停了、也没后台任务时**——不能。我没有"我闲着就主动找你聊天"的能力。除非提前给我挂一个**定时任务**（类似闹钟，设"几点几分提醒你查一下XXX"），到点了系统会触发我，我才"主动"冒出来。这是唯一能让我在没人说话时自己醒来的办法。

简单说：**我像有闹钟的助理，后台活干完会主动汇报，但要我在完全没任务时凭空找你，得先设个闹钟。**

## 一、先给你一个关键数据（决定整个优化方向）

## 二、别人写规则的逻辑（调研提炼，这 5 条是共识）

1. **只写"代码里读不出 + 你每次要重复说"的东西**。技术栈、文件结构、常识——AI 自己翻代码就知道，写进去纯浪费。官方、社区、视频三方完全一致。
2. **把 CLAUDE.md 当"错误日志"，不当"完整规范"**（Claude Code 创始人 Boris Cherny 的方法）：不是一次性写全，而是 **AI 每次犯错，就补一条"以后别这样"**。这样每条规则都有真实场景撑腰，不会空转。
3. **分层放，别全塞一个文件**：建议→CLAUDE.md；强制→hook；多步流程→skill；按路径才用的→rules。判据两问：**「每次会话都要用吗」+「必须 100% 发生，还是 AI 判断就行」**。
4. **控制长度**：越短遵循率越高。
5. **禁令 + 替代成对，强调词克制**：写"NEVER 用 X，改用 Y"，不写"注意代码质量"；`必须`/`IMPORTANT` 这类词少用——每条都强调 = 都不强调。

**排版逻辑**：祈使句（"做完 X 就 Y"）+ 短句 bullet，不用形容词和散文。
