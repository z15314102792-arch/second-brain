# 深井 — 连续下潜型主动增量游戏

> 导航：[[MEMORY]] · [[项目/说明]]
>
> 本文件是《深井》的**唯一设计事实源（Source of Truth）**。  
> 后续 Gemini 3.8 Flash、Codex、Claude 或其他执行模型接手时，必须先读本文件，以“当前有效规格”为最高优先级。  
> 已淘汰、已失效的设计只能用于理解历史，不得重新混回当前方案。

## 0. 项目一句话定义

玩家控制一个角色，在一座**连续、无关卡、理论上无限向下延伸**的矿井中主动挖掘、采集、轻战斗和制作；随着深度增加，不断获得新的工具与能力，突破过去无法处理的资源、环境和敌人，同时逐渐自动化已经落后的劳动。

## 1. 用户偏好与项目边界

- 项目主要是用户自己玩，不把商业化、市场竞争、大众留存当第一目标。
- 更喜欢“人物本人越来越强”，而不是基地或机器成为主角。
- 倾向主动操作；如果完全挂机，会觉得没有参与感。
- 喜欢探索未知，但不希望游戏变成开放世界、生存 RPG、任务驱动或大地图探索。
- 最重要爽点之一：**“以前做不到 / 挖不动 / 打不过，现在终于可以了。”**
- 喜欢《崩溃大陆》的“采集 → 制作 → 角色成长 → 突破新资源/敌人门槛”体验，但只作为体验参考，不照抄其开放世界、基地、任务、剧情与复杂动作战斗。
- 明确讨厌关卡式、章节式、通关式结构。
- 游戏应持续向下，不出现“第一关结束→第二关”“恭喜通关”。
- 理论上无限下潜；开发上只逐步制作有限深度的高质量内容。

## 2. Incremental 核心定义

本项目不是纯 Clicker，也不是纯 Idle。

核心循环：

主动挖掘 / 战斗
→ 获取资源
→ 制作或强化工具、武器、能力
→ 人物明显变强
→ 突破过去无法处理的资源 / 环境 / 生物门槛
→ 获得更高级资源
→ 旧资源逐渐批量化 / 自动化
→ 玩家注意力转移到更深的成长前线。

核心原则：

> **玩家永远工作在成长前线。**

旧内容可以自动化，但不能把当前最好玩的内容也自动掉。

## 3. 前期探索与淘汰记录

### 最初讨论过的方向

1. 最后一台机器：机器修复、模块展开。
2. 口袋流水线：有限空间内优化吞吐。
3. 未知语言：研究并理解未知规则。
4. 微型生态箱：生态系统逐步形成自循环。
5. 远征协议：规划行动后自动执行。
6. 函数工厂：数字经过数学节点形成增长。
7. 失控复制体：控制不断膨胀的复制系统。
8. 城市脉搏：人口增长压垮交通网络。
9. 传播：传播网络增长。
10. 会唱歌的工厂：增长与音乐层次绑定。

### 用户明确 PASS

- 函数工厂：太抽象，不符合资源→工具→能力成长。
- 远征协议：规划后自动执行不是用户想要的参与方式。

### 后续淘汰

随着用户偏好澄清：
- 最后一台机器
- 口袋流水线
- 未知语言
- 微型生态箱
- 失控复制体
- 城市脉搏
- 传播
- 会唱歌的工厂

均不再作为整体候选。个别机制未来可以借用，但不得复活整体方案。

## 4. 候选收敛

曾保留：

### A. 层级荒野
小区域采集、制作、战斗、能力门槛。

### B. 深层矿井
持续向下挖，深度成为唯一清晰成长轴。

### C. 狩猎工坊
采集→制作→狩猎→怪物材料反哺工具装备。

最终：
- **主方案：深层矿井 / 深井**
- 层级荒野：冻结为备用素材库
- 狩猎工坊：不再作为独立候选，只保留“怪物材料反哺工具/装备”的思想

## 5. 为什么选择深井

- 深度天然提供连续目标：“再往下十米看看。”
- 有探索感，不必做开放世界。
- 工具升级容易产生真实行为质变。
- 采集与轻战斗可以自然共存。
- 旧深度天然适合自动化。
- 手机竖屏适配好。
- 7 格宽小地图即可成立。
- 对 Gemini 3.8 Flash 易拆成明确模块。
- 后续扩展可以继续向下增加内容，不需要横向堆大量系统。

## 6. 关键设计变更日志

### 变更 1：从泛 Incremental 发散到角色成长
用户说明自己理解的增量体验更接近：
“执行任务 / 采集材料 → 获取资源 → 解锁能力和工具 → 技能 / 成长。”

结果：抽象系统增长降权，转向“角色能力扩张型 Incremental”。

### 变更 2：角色优先
用户选择“人越来越强”而不是“基地 / 机器越来越强”。

结果：角色是成长主体，机器只承担旧内容自动化。

### 变更 3：主动操作优先
用户倾向“总有东西可以点、可以处理”，否则感觉没有参与感。

结果：不做纯 Idle；采用主动挖掘，自动化只处理旧劳动。

### 变更 4：探索要有，但不能变味
用户喜欢探索，但担心最后变成另一个类型。

结果：采用**能力门槛式局部探索**，不做开放地图。
玩家看到未来资源 / 结构，但当前工具处理不了。

### 变更 5：参考《崩溃大陆》
用户发现当前方向与最近在玩的《崩溃大陆》体验相似。

结果：
可借：采集→制作→成长→突破门槛、减少琐碎背包管理、工具能力改变行为。
不可借：大地图、剧情 NPC、大量任务、基地建造、复杂动作战斗、宠物、装备品质堆积。

### 变更 6：采集 + 轻战斗
用户选择混合方向。

结果：以采集为主体，战斗为动态门槛和材料来源，不让战斗成为第二款 Action RPG。

### 变更 7：矿井成为主方案
用户在“层级荒野 / 深层矿井 / 狩猎工坊”中表示都喜欢，但先推进矿井。

结果：深度成为核心轴。

### 变更 8：核心操作确定
确定：
- 7 格宽
- 挖掘即移动
- 按住挖掘
- 约 70% 爽快破坏 + 30% 路线选择
- 战斗发生在同一格子世界
- 工具必须产生行为质变
- 旧内容逐步自动化

### 变更 9：取消关卡/通关
曾经讨论过“浅层矿区、菌晶洞穴、热裂层”等阶段及约 600m 终点。

用户明确否决：讨厌换关卡和通关型，很容易弃游。

**旧方案失效。**

当前规则：
- 世界是一整座连续矿井。
- 0m → 1m → 2m → …持续下降。
- 资源、地质、怪物和环境随着深度逐渐变化。
- 不出现关卡切换、章节结算、固定终点。
- 内部可以用“深度区间”设计内容，但玩家体验必须连续。
- 理论上无限向下。

### 变更 10：进入可实现规格
用户要求不仅有概念，还必须设计清楚：
- 主界面按钮和功能
- 地图/区域生成
- 材料、资源、怪物分布
- 升级方式
- 获取效率
- 掉落概率
- 合成路径
- 数值是否合理
- 后续执行模型如何实现

结果：建立 MVP v0.1 基线。

### 变更 11：不可逆下潜、真实机会成本与情绪张力
用户指出：如果允许四方向自由挖掘，同时没有体力、耐久等成本，玩家会受到损失厌恶和“不要浪费可见资源”的心理影响，下意识把能挖的资源尽量挖完，导致“路线选择”退化成清图。用户进一步明确：损失本身并不是坏事，有得必有失；路线由玩家自己选择，错过、后悔、懊恼等负面情绪也是有效游戏体验。游戏不应该一味讨好玩家，而应制造真实情绪波动。

结果：
- **取消四方向自由挖掘作为默认核心移动。**
- 核心推进改为“向前下潜”：默认只允许左下、正下、右下三个方向进行挖掘推进。
- 路线选择应具有真实机会成本；玩家选择一条路线后，其他路线可以永久错过，不要求后续轻易补回。
- 错过资源、后悔和损失感可以是设计的一部分，不视为需要被系统自动补偿的风险。
- 但损失应主要来自玩家可感知的信息与自身选择，而不是隐藏的唯一关键道具、不可预知软锁或规则欺骗。
- 主线关键推进资源仍需多次出现或有保底，避免一次随机错过导致存档失效。
- 新增两个向下动力：**深度价值增长**与**连续下潜奖励**。具体倍率先不锁死，待原型测试后调参。
- 前方允许通过颜色、光源、声音、轮廓等“模糊预告”提供不完全信息，让玩家在未知与选择之间产生期待、贪心、犹豫、后悔、惊喜等情绪。
- 设计目标从“始终让玩家舒服”修正为：**让玩家始终在意自己的选择。**

### 变更 12：固定前沿、平滑位移、三格塌落与工具速度重标定
用户试玩包1.1后指出三个直接体验问题：人物随逻辑深度一路下沉而不是保持在主要视野位置；破坏后人物瞬移到目标格，缺少运动过程；斜向进入目标格时会产生“穿墙而过”的空间违和。用户提出：成功选择目标格后，目标所在行以目标为中心的三格都应退出当前地形，其中目标格正常采集并获得资源，左右邻格作为放弃机会向下渐隐消失且不给资源。用户同时反馈 1.2 秒基础破坏过快，无法形成“旧工具很差”的体感。

结果：
- 人物纵向视觉位置改为固定在屏幕约 **65%～72%** 高度的前沿区，逻辑深度继续增加；世界/矿层在推进后平滑向上滚动。
- 目标方块破坏完成后，人物不再瞬移，使用约 **0.18～0.22 秒** 的平滑移动进入目标格。
- 每次成功采集一个目标格后，以目标格为中心处理同一行三格：**目标格获得正常资源；左右邻格直接损失，不产出资源，并用向下坠落 + 渐隐的方式离场**。边界外邻格忽略。
- 这不是“防止玩家损失”的保护，而是把损失视觉化：玩家明确看到自己拿到了什么，也看到自己放弃了什么。
- 未来宽幅/高级工具可以把“左右邻格不回收”升级为“三格全部回收”，作为工具能力质变，因此当前规则与后续成长不冲突。
- 不允许提供“额外花时间把两侧再补挖回来”的基础能力，否则会重新诱发清图。
- 基础挖掘节奏整体拉长，目标是让破旧镐明显笨重，并为工具升级留出体感空间。

### 变更 13：上方固定前沿、点击式挖掘与“破碎时提交”
用户继续试玩包1.2后提出：人物不应先一路下降到阈值后才保持高度，而应从一开始就维持在偏上的视觉锚点，让下方成为主要决策空间；同时希望尝试点击式挖掘，而不是长按固定在目标格。讨论后确认：点击只是“开始尝试挖这个”，真正不可逆选择发生在方块破碎时。

结果：
- 人物视觉锚点改为可玩区域上方约 **30%～35%**，从第一步开始即保持稳定；世界/矿层随推进向上滚动，不再先让人物落到底部附近后再跟随。
- 下方视野不做全量透明展示：建议 **3～4 行清晰可读 + 1～2 行雾化预告 + 更深处黑雾/遮蔽**，保留局部规划与未知感；人物上方保留约1～2行已走过痕迹，维持空间连续感。
- 包1.3加入低成本“矿洞化”：弱化棋盘线、让相邻空洞视觉连通、岩石边缘略不规则、加入少量颜色变化/裂纹/石屑/暗部与黑雾；底层仍保持7格网格，不提前投入正式美术。
- 核心挖掘交互从“持续长按目标格”改为**单击合法目标后自动连续挥镐**。点击后玩家无需继续把手指固定在目标格。
- 挖掘过程中，玩家在目标真正破碎前可以随时取消或改选另一个合法目标。
- **取消或切换目标后，原目标挖掘进度立即清零。** 不允许给多个候选预挖进度后再慢慢选择。
- 取消规则：再次点击当前目标可取消；点击另一个合法目标则切换目标并重新从0开始；点击HUD/无关区域默认不应误取消。
- **选择提交点 = 目标方块破碎时。** 在此之前不结算资源、不增加深度、不触发两侧塌落、不揭示新的正式视野；破碎后才进入不可逆流程。
- 点击式并不等于降低参与感：挖掘期间用连续挥镐、裂纹阶段、石屑、声音/轻震动与最终破碎反馈承载动作感；需观察试玩后是否退化成“点一下等几秒”的被动节奏。
- 人物移动表现继续增强为“下压/前倾 → 进入目标 → 落地压缩/回弹”，总时长约0.22～0.30s，优先优化运动曲线和重量感，而不是堆复杂精灵帧。

### 变更 14：视觉瑕疵不再单独阻塞，进入最小资源闭环
用户试玩包1.3.1后反馈：整体已“没什么太大的问题”，但黑雾仍显不自然，左右洞壁仍不像真实矿洞/土岩材质。讨论后决定不再继续单独迭代纯视觉原型，也不完全忽略问题；下一阶段以验证真正的“选择→资源→升级”循环为主，同时附带一次轻量视觉一致性修正。

结果：
- 包1.3.1视为通过，不再开独立的纯美术打磨阶段。
- 原计划“包2：连续Chunk”顺序调整：**当前包2改为“最小资源闭环（附带1.3.2矿洞视觉一致性修正）”**，优先验证三选一路线在真实资源与第一次工具升级加入后是否仍有持续动力。
- 包2只引入最小经济变量：**石头、铜矿、资源计数、石镐一次升级**；不加入铁、晶体、怪物、完整装备系统、自动化。
- 石镐沿用现有基线：石头×12，挖掘力1.65，普通岩约1.45s；破旧镐普通岩约2.4s。包2的核心验证是玩家是否能明确感到“旧镐很差→第一次升级明显变快”。
- 铜矿进入三向候选后，允许真实错过；目标格正常结算资源，左右塌落格仍无收益。铜矿暂不用于制作铜镐，避免一次加入两级升级导致难以判断第一档成长是否成立。
- 包2内附带1.3.2视觉修正只解决“语义错误”：黑雾去除明显横向硬边/带状分界，左右边缘强化为连续土岩洞壁/地层，而不是普通方块堆叠。**不追求正式美术，不允许视觉修正再次拖住功能验证。**
- 连续Chunk、正式深度生成与基础存档顺延到包3；包2允许沿用现有滚动/补行机制完成3～5分钟资源闭环试玩。


### 变更 15：锁定主叙事《井在向下生长》，叙事与成长统一为“理解并利用井脉”
用户针对“为什么来矿井、为什么继续下潜、为什么收集资源与制作工具”的动机缺失问题，单独完成了一轮剧情设计。经过三个方向比较，正式选定 **《井在向下生长》** 作为主叙事骨架：玩家最初只是执行一次普通废矿复勘，但随着深入逐渐发现，所谓“深井”并不是某个文明从地表一路向下挖出的超深矿道，而是一种会在压力/温度条件下持续形成规则结构、迁移矿物并传播机械振动的异常地质系统。暂称该深层规律为 **“井脉”**。

本轮补充并锁定以下修订：
- **初始任务不能在发现铜后就结束**。正式任务表述改为：确认震后新通路的矿化情况，并在安全条件允许下继续确定矿带范围与旧巷道状态。第一次发现铜只回答“下面还有没有矿”，随后自然转入“矿带到底延伸多深/旧记录为什么对不上”的下一目标。
- 玩家身份锁定为 **深层维护员 / 下探矿工**，擅长狭窄矿道作业、现场维修、判断岩层和临时改造采掘工具；不是科学家、特种兵或考古学家。
- 不采用失踪亲友、失踪勘探队、世界危机或“必须阻止某物毁灭世界”作为长期驱动力。长期动力是：**理解井脉、利用新规律、看看更深处还能出现什么。**
- “古代文明”降级为 **前代使用者 / 未知年代使用者**。他们不是故事主体，也不是井脉创造者；只是在更早时期学会利用井脉。其“先进”只限定在对井脉的利用技术，不等价于全领域超越现代。
- 工具成长从“材料等级越来越高”改为 **材料工程性质逐步解锁**：石材提供耐磨楔面；铜用于导电/恢复振击组件；铁提供结构强度；晶体提供共振能力；古代核心提供自动控制。现有“石镐”名称可暂时保留为系统名，但正式表现应避免“捡石头绑成原始石镐”的违和。
- 浅层 0～120m 可使用连续安全索/牵引解释受伤回退；更深处以后由玩家沿途自动部署 **中继锚点/牵引节点** 延伸回收与通讯能力。它是世界观基础设施，不增加主动建造玩法。
- 三格塌落采用“双层解释”：浅层是楔入式开孔导致小型承压单元应力重排；越深以后玩家才发现这种三向/单通道失稳规律整齐得异常，反过来成为井脉存在的证据。规则只解释一次，不长期用台词重复说明。
- 叙事密度锁定：普通下潜不讲话；新材料/新规则第一次出现最多一句；大型发现 2～4 句；环境信息优先通过画面与声音表达。30 分钟内强制剧情文字原则上不超过二三十句。

## 7. 当前核心支柱

1. **点击启动自动挖掘 + 左下 / 正下 / 右下三向路线选择**
2. **不可逆下潜 + 真实机会成本**：不能什么都拿，路线选择允许造成永久错过
3. **工具成长改变破坏方式**
4. **采集与轻战斗互相提供材料**
5. **旧内容逐渐自动化**
6. **玩家永远工作在最深的成长前线**
7. **连续下潜产生局部未知**
8. **深度价值增长**：越深，资源的平均价值和新内容期望越高
9. **连续下潜奖励**：持续推进应获得正向收益，强化“继续往下”的动力；具体倍率待试玩调参
10. **情绪张力优先于无条件舒适**：允许贪心、犹豫、错过、后悔、惊喜等情绪，只避免无信息惩罚和不可恢复软锁

## 8. 主界面与交互

### 画面方向
- 手机竖屏。
- 默认纯像素风。
- 初期只做占位级像素素材，优先保证反馈。
- 包1.3开始做**最低成本矿洞化**：弱化规则棋盘边框，相邻空洞视觉连通，岩块边缘加入轻微不规则和少量色差，并加入裂纹、石屑、暗部与黑雾；底层逻辑仍保持7格网格。
- 当前不投入正式角色/矿石/场景美术，目的只是消除“方格测试程序”的视觉误导。

### 主界面

顶部：
- HP
- 当前深度
- 历史最深深度

中部：
- 7 格宽矿洞
- 人物从第一步开始固定在可玩区域上方约 30%～35% 的视觉锚点
- 下方约 **5～6 行清晰可读**，随后 **2 行半雾化预告**，更深处由黑雾/遮蔽隐藏
- 人物上方保留约 1～2 行已走过痕迹，用于维持空间连续感；不提供自由回头

资源栏：
- 默认显示当前最相关 3～5 种资源
- 可展开全部资源
- 无限背包，不做容量管理

底部：
- 制作
- 装备
- 采掘（自动化解锁前隐藏）
- 菜单

暂不增加其他主导航。

### 操作

- 核心推进只允许三个前向方向：**左下、正下、右下**。
- **单击**三个前向合法目标之一：立即开始自动连续挥镐，不需要持续长按目标格。
- 方块真正破碎前可以随时取消或换目标；再次点击当前目标=取消，点击另一个合法目标=切换。
- 取消/切换后原目标挖掘进度立即归零，不保留预挖进度。
- 点击 HUD 或无关区域默认不应误取消当前挖掘。
- **方块破碎才是选择提交点**：此时才结算资源、触发左右邻格塌落、推进深度并揭示新视野。
- 方块破坏后：角色进入该格，同时深度推进。
- 前方为敌人时后续可沿用“点击目标→自动攻击”的同类交互，但战斗包再具体实现。
- **默认不允许向上挖、横向清图或自由回头。**
- 玩家选择的路线允许造成真实且永久的机会损失；不保证所有可见资源最终都能获得。
- 特殊工具未来可以有限打破方向规则（例如横向穿透），但这是能力奖励，不是初始自由度。
- 挖掘即移动。
- 不设虚拟摇杆。
- **固定前沿显示**：人物逻辑位置持续向下，但从第一步开始屏幕纵向位置长期保持在可玩区域上方约 30%～35%；每次推进后矿层/世界平滑向上滚动。下方保留 **5～6 行清晰内容**，随后 **2 行半雾化预告**，更深处进入黑雾。
- **进入目标格动作**：目标破坏后，人物用约 0.22～0.30 秒完成“下压/前倾 → 进入目标 → 落地压缩/回弹”，不允许坐标瞬移或匀速UI式滑动。
- **三格塌落规则**：成功采集目标格 `(tx, ty)` 后，目标格正常产出；同一行 `(tx-1, ty)` 与 `(tx+1, ty)` 若存在则作为未选择机会退出地形，不产资源，并向下坠落 + 渐隐。
- 邻格损失必须可见但反馈简洁；它表达真实机会成本，不做自动补偿。
- 后续宽幅工具可把邻格从“塌落无收益”升级为“同步有效采集并获得资源”，作为工具质变。

### 路线选择与情绪规则

- 玩家不应该拥有所有东西。
- 不同方向尽量提供**不同类型价值**，例如资源、深度、战斗材料、未知结构，而不是简单的高低价值答案。
- 错过和后悔是允许的有效体验；不要自动补偿玩家每一次损失。
- 前方信息可以不完整，但应有可读线索，例如蓝光、红色闪动、金属声、虫鸣、裂缝轮廓等。
- 允许玩家因贪心多拿资源而牺牲更快下潜，也允许为了深度放弃眼前收益。
- 关键主线材料不得只通过一次不可预知分支获得，避免随机软锁。

### 向下动力

1. **深度价值增长**：更深处同类资源的平均产出、矿脉质量或高价值内容期望应更高，使“继续向下”具有直观经济价值。
2. **连续下潜奖励**：连续推进一定深度后，逐渐获得矿脉发现率、稀有内容概率或类似正向加成。当前只确认机制，不锁定具体数值，需通过原型测试。
3. 不采用氧气倒计时、体力衰减、工具耐久等强迫式推进作为MVP核心。

明确不做：
- 向上自由挖掘
- 横向自由清图
- 长距离回头扫图
- 跳跃
- 平台动作
- 精准闪避
- 连招
- 武器实时瞄准
- 大地图自由移动

## 9. 地图与 Chunk

逻辑 Chunk：
- 7 格宽 × 12 格高
- 约 12m 一个 Chunk
- 玩家接近底部时提前生成下一 Chunk
- 玩家看不到 Chunk 边界

玩家不知道它存在。
目的只用于防止随机地图把玩家完全堵死。

## 22. 120m 以后

120m **不是通关点**。

当前 MVP 只认真设计 0～120m 内容。
超过以后：
- 继续生成已有资源与怪物
- 敌人 HP 每额外 100m 约 +25%
- 敌人攻击每额外 100m 约 +15%

## 23. 技术实现建议

### 引擎
推荐 Godot 4.x 稳定版。

执行前由开发模型检查本机实际安装版本；不要为了追最新版本主动折腾环境。

### 脚本
推荐 GDScript。

### 美术
默认纯像素风。
原因：
- 7 格宽格子矿洞天然适配
- 素材量小
- AI 辅助生成和手工替换都容易
- 移动端清晰
- 与破坏反馈、资源识别兼容

### 架构模块

1. Grid：7 格宽坐标与格子管理
2. Chunk：连续向下生成、加载、卸载
3. Tile：方块数据
4. Mining：阻力、硬度、工具和破坏
5. Player：位置、HP、装备
6. Enemy：HP、行为、环境互动
7. Inventory：资源数量，无容量限制
8. Crafting：配方与发现解锁
9. Progression：深度、最深深度、保底事件
10. Automation：采掘机在线/离线结算
11. Save：存档与版本基础

### 数据驱动

资源、方块、工具、武器、核心、怪物、配方、生成概率尽量配置化。

工具能力应抽象为能力类型：
- 单格挖掘
- 连锁
- 穿透
- 范围破坏

## 29. 当前主叙事事实源：井在向下生长

### 一句话主线
一座已经废弃的普通矿井，在一次地质震动后重新出现向下通路。玩家作为深层维护员进入复勘；随着深入，他逐步发现：所谓“深井”并不是谁从地表一路挖出的巨大通道，而是一种会利用地下条件持续形成规则结构、重新组织矿物并传播机械振动的异常地质系统——**井脉**。以前的人类曾利用它，现在玩家也开始利用它。

### 玩家与初始任务
- 玩家身份：深层维护员 / 下探矿工。
- 初始任务：确认新通路的矿化情况，并在安全条件允许下继续确定矿带范围与旧巷道状态。
- 0～15m第一次发现铜，只回答“下面还有矿”，不代表整个任务结束。
- 后续任务自然转为：矿带到底延伸多深？为什么旧矿井档案逐渐对不上？谁曾在更深处利用这里？

### 长期动力
- 故事动力：**下面还有一种我不知道的规律。**
- 成长动力：**我要获得能让我进入、处理和利用那种规律的能力。**
- 最终不是寻找固定井底、Boss或世界危机；每一阶段应给出真实答案，同时打开新的更深问题。

### 井脉三条基础规律（当前锁定）
为了防止“井脉”退化成万能魔法，未来新增剧情/玩法优先从以下三条派生；确实无法派生时才讨论是否增加第四条规则：
1. **应力重排**：地下压力促使岩层形成局部规则裂隙、承压单元和稳定通路。解释三格塌落、异常规则断面、深层单通道倾向等。
2. **矿物迁移/富集**：在长期压力与温度条件下，特定矿物沿井脉结构重新分布与富集。解释废矿深处反而出现更高价值矿物与异常矿脉。
3. **机械共振传播**：部分井脉结构能高效传递机械振动。解释晶体、共振核心、连锁破坏、深层钻进，以及前代装置为何能“接入”井脉。

### 前代使用者
- 不建立“万能超古代文明”作为故事主体。
- 统一称为前代使用者/未知年代使用者，正式剧情早期甚至不必命名。
- 他们并未创造井脉，只比现代矿站更早发现并利用其规律。
- 他们的优势限定在井脉适配/采掘技术，不代表所有技术全面超现代。

### 工具成长的叙事原则
工具升级不再解释为“石→铜→铁所以单纯越来越硬”，而是每种材料解锁新的工程性质：
- 石材：耐磨楔面/临时修复破旧镐头；
- 铜：导电，恢复/增强旧工具的振击组件；
- 铁：结构强度与承载；
- 晶体：机械共振；
- 古代核心：读取/控制已理解的井脉规律，支撑自动化。

因此“材料发现→配方出现”必须尽量表现为角色理解了材料的性质，而不是系统凭空奖励配方。

### 不可逆与回收解释
- 浅层：连续安全索与井口牵引系统。
- 深层：自动铺设中继锚点/牵引节点，延长回收与通讯范围；不增加主动搭建设备的玩法负担。
- 玩家可以被回收到稳定点，但塌落矿体、错过资源与旧路线不会复原，因此路线选择保持不可逆。

### 三格塌落的世界内解释
浅层先按真实工程直觉解释：玩家采用楔入式承压层开孔；主裂面贯通后，相邻两个承压位一起失稳、剪切和滑落。越深以后玩家才发现这种“每次都形成规则单通道”的行为整齐得异常，并将其视作井脉应力重排规律的证据。

## 33. 包 2.2：存档系统与全局音频反馈基础落地记录 (2026-09-11)

- **核心定位**：正式内容开发前的纯基础设施包，彻底解决“重新进入从0开始”和“音频未解耦/覆盖不全”两大技术痛点。不增减任何新怪物、新资源、新关卡或新剧情。
- **正式存档系统 (SaveSystem)**：
  1. **双端数据结构对齐**：统一保存版本号 `save_version: 1`、时间戳、玩家坐标与深度、背包资源（石材/铜矿）、工具类型与挖掘力、配方解锁状态、当前目标、开场阶段、剧情触发历史字典、世界网格状态与音量总线设置。
  2. **不可逆路线记忆复原机制**：因三选一塌落机制，世界状态不仅存深度，而是记录全部 `cleared_cells` 坐标集合（已挖目标格与两侧塌落格）。反序列化时恢复基础网格并应用 `cleared_cells`，100% 还原玩家开采不可逆路线与塌落废墟，且未挖方块变体一致、绝对 0 闪烁。
  3. **写入安全与坏档容错**：Godot 端采用原子写入（`user://save_v1.tmp` 写入 -> 备份旧档至 `.bak` -> 重命名提升为 `.save`）；读取时若 JSON 损坏或截断，自动无缝回退加载 `.bak`，绝不白屏崩溃。
  4. **自动保存时机**：每次挖掘破碎完成瞬间、每次工具改造完成瞬间、开场落地进入游玩瞬间、以及每 30 秒兜底定时保存。
  5. **重置功能**：Godot HUD 与 Web 端顶部均提供显式【↺ 重置存档】入口，点击确认后彻底删除磁盘/localStorage 存档，内存状态清零并回到地表重新开始。
  6. **Web 存储特性与临时域名说明**：Web 端采用 `localStorage`（键名 `deep_mine_save_v1`）。由于 Cloudflare 临时隧道域名重启后可能会变换二级子域，浏览器会按 Origin 隔离数据。因此推荐手机通过内网固定 IP `http://192.168.0.95:8089` 访问以保证存档绝对持久。
- **全局独立音频系统 (AudioSystem / AudioManager)**：
  1. **彻底解耦**：建立独立的全局 `AudioSystem` / `AudioManager`，剧情与主循环中仅做干净调用。
  2. **6 大分组全覆盖**：
     - UI：普通点击、拒止禁用、确认制作、目标推移三连音；
     - Mining：挥镐轻啸、命中岩石沉闷敲击、命中铜矿清脆撞击、裂纹阶段（35%/70%脆响递增）、方块最终破碎（噪波破裂）、邻格塌落沉响、资源进包音；
     - Player & Craft：落地冲击、检视破旧镐、镐刃断裂崩损、改造锻打打铁声（音调递增）、工具改造完成和弦；
     - Narrative：无线电接通静电哔声、步话机沙沙微静电、说话 voice blip 嘀嗒轻音、发现神秘和音；
     - Environment：偶发远处深坑落石回响（15~25s 自动随机调度）。
  3. **防爆音与防轰炸机制**：
     - 0.08s 同类声音冷却节流，彻底消除高频点击导致的耳膜撕裂感与破音；
     - 小范围 pitch 随机浮动（±6%）与音量微随机（±8%），避免长期镐击产生机械重复感。
  4. **移动端手势解锁**：Web Audio 增加首次用户触控 `audioCtx.resume()` 唤醒静音脉冲，配合压限器保证真实手机外放清晰可听。
- **验收验证**：
  - Godot Headless 运行 `tests/test_runner.gd`，**全量 29 项验收测试 100% 绿色全过 (29/29 PASSED)**；
  - Web 端在本地 `8089` 与 Cloudflare 隧道热更新并自测正常。

### 包3：连续Chunk与正式深度生成（当前执行）

**核心目标**：把当前原型式持续补行升级为真正可长期向下扩展的连续世界结构，为后续硬岩、铜镐、战斗等内容提供稳定地基。包3是技术基础阶段，不用它判断“游戏是否已经有趣”；包3通过后立即进入包4，用能力门槛与工具质变开始验证核心乐趣。

1. **Chunk结构**
   - 逻辑Chunk固定为 **7格宽 × 12格高**，约12m一个Chunk。
   - `chunk_index = floor(world_row / 12)`；玩家体验始终是0m→1m→2m连续下降，绝不出现“进入下一关/下一层”的提示。
   - 玩家接近当前Chunk下沿前，必须提前生成后续Chunk；Chunk边界对玩家完全不可见。
   - 运行时只保留合理活动窗口，优先采用“当前Chunk + 下方2个预生成Chunk + 上方至少2个历史Chunk/必要状态”，避免深度增长后内存无限膨胀，同时为后续死亡回退约10m预留空间。实际数量可按性能测试微调。

2. **确定性世界生成**
   - 建立并保存 `world_seed`。
   - 每个Chunk必须由 `world_seed + chunk_index` 确定性生成：同一存档无论刷新、卸载、重载，同一个未被改变的Chunk内容和 `variant_id` 必须完全一致。
   - 生成顺序继续遵守：保证可达主通路 → 填充岩石 → 矿脉 → 空腔/保底接口 → 校验。包3暂不正式加入硬岩、铁、怪物等包4以后内容，但架构必须允许后续按配置接入。
   - 第一条铜矿8～12m保底规则继续成立；现有普通岩/铜矿视觉变体与机会成本规则保持。

3. **隐形可达主通路**
   - 每个Chunk先生成一条轻微左右摆动的理论可达路线。
   - 路线只用于防止程序生成把玩家彻底锁死，玩家不可感知“主通路”的存在。
   - 当前只使用已有可挖材料，后续加入硬度门槛时，主通路硬度不得超过该深度按正常进度应拥有的工具能力。

4. **正式深度系统**
   - 深度由世界绝对行统一计算，不能依赖当前屏幕局部坐标。

### 背景与真实手机问题
在 Android A0 首次真机验收中发现原生版本存在多项严重回归与体验缺陷：

### 根因分析与彻底修复方案
1. **开场人物不动根因**：`src/main.gd` 的 `_process` 尾部 `player.position = get_cell_center(player.grid_pos)` 缺少 `opening_phase == 4` 阶段保护，导致下井阶段每帧计算出的下降位移被强行覆盖回地面 (3, 0)。
   - **修复**：增加阶段严格分支判断，下井阶段人物坐标仅由钢索动力学平滑驱动。
2. **标题页与人物重叠根因**：标题界面此前手绘且场景中的 `player` 节点在 `_ready` 初始化在 (180, 208) 未被隐藏，直接画在文字上面。
   - **修复**：重构为标准 Godot 控件 `TitleScreen`（`src/ui/title_screen.gd`），大标题、居中矿工徽标留白容器、副标题自适应排列；在阶段 0 时强制 `player.visible = false`，彻底互斥。
3. **设置无反应与卡顿根因**：Godot 原生之前只画了假文字弹窗，且只在阶段 0 绘制，游戏内（阶段 4）点了设置后 `show_settings_dialog = true`，不仅画面没画出来，还把后续所有挖掘点击当成了设置拦截，导致游戏“假死”。
   - **修复**：实现全新通用设置面板 `SettingsDialog`（`src/ui/settings_dialog.gd`），支持主音量/音效/环境音量 HSlider，实时调节 AudioSystem 并原子化持久化到 SaveSystem。
4. **Android 完全无法挖矿根因**：
   - 坐标映射偏差：未做 Canvas 逆变换直接比对；
   - 触摸与模拟鼠标双触发：Android 触控派发 `InputEventScreenTouch` 后，引擎模拟鼠标事件紧随其后到达，第 1 个事件启动挖掘，第 2 个事件瞬间命中“再次点击取消”，0ms 内瞬间取消挖掘；
   - 临时 UI 遮罩拦截：Control 节点的 `mouse_filter` 穿透拦截。

## 32. Android Build A0.3：音频反馈、UI可读性、主题系统与制作页修复（2026-09-12）

### 真实手机反馈痛点与根因排查
1. **P0 制作页卡死/无法关闭/认知混乱**：
   - **根因一（致命父节点裁剪）**：`HUD` 顶部栏在 `main.tscn` 中高度被固定为 76px。旧制作面板作为其子节点，超出 76px 的区域（包含弹窗主体与关闭按钮）完全无法被父节点接收触摸事件；
   - **根因二（状态机未接入）**：没有独立的 `AppState.CRAFTING`，无法响应 Android 原生返回键退栈；
   - **根因三（关闭按钮热区过小）**：仅 28×26px，手机端长屏极难触中；
   - **根因四（认知障碍与剧透）**：未清晰展示工具成长路径与清晰材料消耗图纸。
2. **P1 音效存在感极弱（实为完全无声假信号）**：
   - **惊天根因**：`AudioSystem` 虽然定义了 `sound_played` 信号，但工程中没有任何 `AudioStreamPlayer` 节点或实际音频数据，原生端完全静音！
   - **节律缺失**：挖矿 2.4s 期间，仅 35% 和 70% 发出裂纹声，中间漫长静默，缺乏持续敲击打击节奏。
3. **P1 全局 UI 深色矩形底框几乎看不见**：
   - **根因**：卡片 surface (0.07) 与背景 (0.03) 明度差过小，在手机长屏 OLED/IPS 上与底色严重混化，轮廓无法辨认。
4. **P2 主题系统与深浅模式缺失**：
