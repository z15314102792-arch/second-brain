### 2026-07-30：调研先行确立

用户多次合作中发现跳过调研直接写代码导致基础问题反复出现。写入 CLAUDE.md"调研"板块：做任何功能前先搜同类方案、了解常见坑，禁止跳过调研直接写代码。参考 [[调研先行]]。

29 条规则 → 16 条、7 个板块。新增大项：测度五维度轮换、小白友好、用户审批规则、编码前自查三问。旧版备份到 [[CLAUDE备份]]。

同日后半段：搭建记忆系统，新增"会话存档"板块——自动存档 + git push。

### 2026-08-06 上午：找回项目规则（新增后删除）

新增"claude continue 找不到项目时"的自动触发规则 → 分析发现使用频率极低 → 删除。确立了筛选原则：**每次会话都用到的行为准则 → CLAUDE.md，偶尔参考的应急流程 → memory。**

### 2026-08-06 下午：手机方案调研 + 两条自查规则

调研过程中观察到用户决策规律（问题在我看来的致命问题、放到用户的使用场景下其实不是问题），写入两条：

- 编码前自查新增第四问：我判定的问题，放在用户的实际使用场景下还是问题吗？
- 改 CLAUDE.md 前自查三问：能落地吗 / 有更省的吗 / 有副作用吗

### 2026-08-06 晚间：全局指令审计 + 三条修复

逐条审计发现三个盲区：

| 问题 | 修复 |
|------|------|
| 自测五维度只适合游戏/Web | 加豁免：纯文档项目跳过，改查引用和格式 |
| 版本标示假设所有项目是 Web | 改为"按项目类型选合适位置" |
| 存档判断缺"纯分析讨论"场景 | 新增：无文件改动时用对话主题关键词匹配 |

### 2026-08-06 深夜：Agent 分派标准重写

发现"简单任务直接做"的判断标准太粗糙。重写为：不需要读文件和做判断的纯信息收集自己直接做；目录分散或命令超过 5 条时例外，可分派。

### 2026-08-06 深夜：规则太绝对问题讨论

三条规则（调研先行、自测、版本标示）中的"每次/必须/禁止"会导致微小操作触发重型流程。分析了三种写法（绝对、模糊、默认+例外）对 LLM 的执行差异。决定加微小改动豁免。

同场讨论：中文 vs 混合格式（结构化+正反例）。结论——当前规则 < 20 条，纯中文足够。超过 25 条或出现互斥时切换。

### 2026-08-06 深夜：有更好的就说

讨论了为什么 Claude 不会主动提醒用户"有更好的做法"（默认模式是问什么答什么）。写入：回答完后发现更优方案提一句、问要不要展开；不确定的不说。
