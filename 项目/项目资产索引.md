# 项目资产索引

> 目的：新设备或磁盘故障后，能够从第二大脑反查所有正式项目本体、Git 状态和灾备位置。
> 正式项目本体统一保留在 `E:\项目`；本文件只做索引，不复制工程本体。

## 恢复总入口

- 项目本体根目录：`E:\项目`
- 项目灾备：Google Drive `04_项目灾备/<项目名>/`
- 灾备脚本：`E:\第二大脑\scripts\backup_projects_to_drive.py`
- 计划任务：`Project Drive Backup`，每天 03:30；内容未变化时不重复生成项目 ZIP。
- 第二大脑 Git 元数据灾备：Google Drive `03_第二大脑备份/git-bundle/`
- Drive 只保存不可变灾备快照，不对 `E:\项目` 做实时双向同步。

## 特殊恢复说明

- `deep-mine/android/keys/deepmine.keystore` 与 `pvz-godot/android/keys/pvz.keystore` 是恢复关键凭据：不进入 Git，但进入私人 Drive 项目灾备。
- Godot `.godot/`、`builds/` 和已确认的导出构建目录属于可再生成内容，默认不进入项目 ZIP；源码、场景、资源、配置、测试和交接文档保留。
- `ai-quota-monitor` 当前存在未提交修改，因此不能只依赖其本地 Git HEAD；Drive 项目 ZIP负责保存当前工作区状态。
- `ai-quota-monitor`、`autoclip-web`、`deep-mine`、`pvz-godot` 当前没有 GitHub 远端；在远端补齐前，异机恢复依赖 Drive 项目灾备 + 本地 Git 历史随 ZIP 保存。
- 空目录 `E:\项目\AI项目`、`E:\项目\Codex项目` 和 Drive 遗留 `.tmp.driveupload` 不视为正式项目资产。

## 新设备恢复判定

只有当第二大脑、项目索引、项目 ZIP、必要 GitHub 仓库及关键凭据都能重新取得时，才可判定“项目与知识资产已恢复”；仅看到同名文件夹不算恢复完成。
