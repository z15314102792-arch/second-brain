# AI 短剧 / AI 叙事视频创作学习

> v1.3 | 2026-09-15。来源：普通对话《AI短剧流程分析》《制定AI短剧方案》，用户于本日明确要求补存。本文保存学习约定和生产方法，不把旧工具推荐、未确认规格或未完成作品写成已验收事实。

## 用户目标与配合方式

- 用户有基础视频剪辑经验，对AI视频生成、分镜和角色一致性属于零基础。
- 主要目的不是立即赚钱，而是做出完整作品，积累可持续的创作能力，并判断是否适合长期学习。
- 衡量标准是以较低成本、简单流程持续做出质量合格的完整作品；不能把学习变成不断研究工具。
- 免费优先。初期不主动引入高价订阅、API、云GPU、本地模型、ComfyUI、LoRA、付费工作流或多个会员；只有免费方案明确妨碍质量或效率时再讨论付费。
- AI主动引导，每次推进当前一步；告诉用户为什么做、做什么、去哪里、输入什么、合格结果和失败处理方法。专业上能判断的直接判断，个人审美和故事大方向由用户把握。
- 采用项目制学习，遇到概念再解释；不先灌输长课程，不提前自动化尚未稳定的手工流程。

## 当前作品与阶段

当前学习作品为 [[项目/AI短剧_失踪者名单/00 项目总控/项目导航]]，女频恋爱、危险关系与悬疑方向；第一章已暂定定稿，当前已进入第一集 Flow 图片生产试跑。

故事、人物与悬疑的当前事实以该作品的当前有效设定为准。先把故事因果和人物写成立，再做短剧改编，最后进入AI镜头生产；不能为了卡点破坏故事。

早期曾建议20～40秒实验片、逐渐扩至30～60秒和60～90秒，属于学习阶梯建议，不是《失踪者名单》的最终时长或集数。后来作品发展为连续叙事；从其中选择一个完整场景做短片实验是待讨论办法，尚未锁定。不能以固定秒数强行截断故事。

本项目与 [[项目/AI短剧解说视频]] 的历史VideoClaw自动配画面项目不同，不能自动沿用其工具、付费API和待办。

## 轻量制作流程

故事 / 剧本 → 固定角色、场景、服装及关键道具 → 角色与场景参考图 → 镜头表 → 分镜 / 起始画面 → 图生视频或参考图生成视频 → 声音 → 剪辑 → 连续性与质量检查 → 分析并重做失败镜头。

- 不直接从长剧本跳到整段视频。构图和角色外观在图片阶段先解决，视频生成是后续生产环节。
- 一个总控会话维护故事和连续性，不初期拆出编剧、导演、分镜、提示词、审片、模型测试等大量会话。多集、多角色、大量镜头时才考虑增加镜头生产会话，主版本仍唯一。
- ChatGPT承担故事、人物、镜头规划、参考图需求、提示词、连续性检查和失败分析；其图片能力满足需求时优先直接使用，明确不足时再引入其他生图工具。
- 学习初期以一个主视频工具为主，必要时一个备用；后期用剪映剪辑，再回总控审片。避免同时学习一串平台。
- Flow/Veo、Vidu、即梦/Seedance、Kling等是当时讨论过的候选，未冻结为当前必用工具。执行前重新核实地区可用性、套餐模型、功能、额度、单镜头成本和操作难度；不把聊天里的1050积分或每日50点作为长期固定额度。

## 额度与版本管理

1. 先测试镜头，合格后再做最终版本；有低分辨率测试时先使用。
2. 图片构图不合格先修图，不让视频模型反复碰运气。
3. 失败先分辨是模型限制、操作、提示词、分镜还是工具选择问题，再重做；不能默认“再生成一次”或把所有失败归因于提示词。
4. 记录通过版本，不重复生成已合格内容。镜头统一编号，如S03；版本如S03-V1废弃、S03-V2通过。
5. 镜头表保存时长、景别、运镜、内容、人物位置、提示词、生成版本、审片结果及失败原因。
6. 项目资料逐步记录当前故事、人物外观与关系、场景结构与光线、关键道具、镜头及未解决剧情线。用作品已有模块维护，不再另建第二套总档案。

## 每个镜头的审片清单

1. 人物脸是否一致。
2. 服装是否一致。
3. 发型是否变化。
4. 年龄是否变化。
5. 左右位置是否错乱。
6. 道具是否消失。
7. 场景结构是否变化。
8. 动作是否符合物理逻辑。
9. 手部、脸部是否异常。
10. 是否有无意义运镜。
11. 表演是否符合剧情。
12. 能否与前后镜头衔接。
13. 时长与节奏是否拖沓。
14. 音频是否自然。
15. 这一镜是否有存在必要。

剧情弱、角色漂移、节奏差、AI痕迹重或成本过高时直接指出，不能为鼓励而降低标准，也不能因已生成就舍不得删除不合格镜头。

## Flow 图片生产试跑得到的通用方法（2026-09-15）

### 1. 角色母版与生产图分层
- 原始角色视觉设定是身份真源；Flow角色、高清复现图、正式镜头图都是生产资产，不能因为更清晰就反向替换原母版。
- 角色参考优先拆成干净的“脸部近景 + 正面全身”两张图，分别承担五官身份与体型/服装；整张多视角拼版直接喂模型容易造成信息竞争。
- 表情页只承担表演参考，不覆盖身份母版。

### 2. 模型选择必须靠项目实测
- Nano Banana 2 在当前项目多次偏向通用动漫脸、2.5D / 3D和偏真人材质，暂不作为最终图片主模型。
- Nano Banana Pro 在同样参考条件下更能保持二维国创写实动漫方向，因此当前作为图片主模型试跑。
- 不把单次好图当模型已通过；至少验证单人、双人、近景与固定场景组合。

### 3. 提示词先翻译成“可见变量”
不要直接把小说语言、内部项目名或抽象心理状态交给图像模型。

错误倾向：
- “保持《失踪者名单》的风格”；
- “韩东错认姜昭”；
- “情绪防线短暂松动”；
- “低存在感”“不要男主化”。

正确做法：先由总控理解剧情，再翻译成模型可直接画出的内容：
- 摄像机在哪里、朝向哪里；
- 人物在画面什么位置、占比多少；
- 谁坐哪把椅子，桌沿、椅面、椅背、腿和脚是什么几何关系；
- 眼睛、眼睑、眉心、嘴唇、头部、肩膀具体怎么变化；
- 哪些内容必须完全不变。

一句话：**剧情意图 → 可观察动作 / 几何关系 → 模型提示词。**

### 4. 多参考图必须明确职责
每张参考图都要写清只负责什么，例如：
- `@角色`：脸、发型、年龄、服装身份；
- 上一镜通过帧：人物位置与空间连续性；
- 场景母版：门窗、桌椅、柜子等结构；
- 风格参考：只负责线条、材质和光影。

同时约束越多，模型越容易顾此失彼。失败时应减少参考职责，而不是继续叠加提示词。

### 5. 不再把“再抽一次”当默认修复
先判断失败属于：身份漂移、空间漂移、构图、局部角色、风格还是模型能力。
- 大结构错误：回到母版 / 已通过帧重新生成；
- 局部错误且主体已通过：局部编辑；
- 同一失败连续出现：改输入结构或模型，不无限抽卡。

### 6. 生产试跑再进入全量生产
正式整集逐镜前，先选 2～3 个代表镜头完整跑通：建立镜头、角色近景微表情、双人 / 反打连续性；静帧通过后再试视频。只有身份、空间、动作、成本和返工次数均可接受，才进入整集生产。
