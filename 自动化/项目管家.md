# 项目管家 — AI 自动化系统

**版本**: v2.1
**创建**: 2026-08-07

## 是什么

基于 Claude Code 的 Skills + Workflows + Cron + **GitHub Actions 云端工作流**四层自动化系统。

## 架构

```
Skills（可复用技能）
  ├── /项目体检      → 单项目全面健康检查
  ├── /全项目体检    → 4项目并行扫描+汇总
  ├── /记忆体检      → 记忆库健康扫描
  └── /记忆周报      → 本周学习总结

Workflows（多Agent并行编排）
  └── 全项目体检.js  → 4 Agent 并行检查 → 结构化报告

Cron（定时自动化）
  └── 每天 9:03     → 静默巡检，有问题才报告

GitHub Actions（云端工作流，不依赖电脑开机）
  └── daily-brief.yml → 每天 8:57 综合日报（AI新闻+项目巡检+微信推送，三合一）

Hooks（事件触发）
  ├── PostToolUse   → 写文件后自动提醒版本号/测试
  └── SessionEnd    → 会话结束提醒存档
```

## 决策记录

### 为什么 Workflow 而不是纯 Skill？
- Skill 只能串联执行（一个接一个）
- Workflow 的 `parallel()` 能真正做到 4 Agent 同时工作
- 预期：4 个项目体检从 ~2 分钟（顺序）降到 ~30 秒（并行）

### 为什么是 Cron 而不是 Loop？
- Loop 需要 Claude Code 持续运行，不适合"每天一次"的场景
- Cron 是持久化定时器，即使重启也保留
- 设为 9:03 而非 9:00 避免整点拥堵

### 为什么 GitHub Actions 里 Python 代码要外置为独立文件？

- Workflow YAML 的 `run: |` 块中包含 Python 代码（无论 heredoc、`-c` 单行还是任何内联形式）会导致 GitHub 解析器丢掉 `workflow_dispatch` 触发器
- 花了十几次迭代才定位到根因
- 解决方案：Python 代码放 `scripts/*.py`，workflow 只写 `run: python3 scripts/xxx.py`
- 这是 GitHub Actions YAML 解析器的 bug，不是我们写错了

### 为什么项目 CLAUDE.md 放在 .claude/ 而非根目录？
- 避免部署到 GitHub Pages 时暴露
- Claude Code 会递归向上查找 CLAUDE.md
