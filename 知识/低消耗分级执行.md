# 低消耗分级执行

## 核心结论

降低 Codex 额度消耗的关键不是少验证，而是把任务拆层：本地命令直接做，轻量调研和草稿优先交给低成本模型，Codex 负责最终判断、危险操作和复核。

日志不能降级。保存进度时，日志必须完整记录做了什么、为什么做、改了哪些文件、当前状态和下一步。

## 执行规则

1. 0级本地命令：查状态、下载、解压、校验、启动、明确路径删除、`git status` 等，直接用本地命令，不额外调研。
2. 1级轻量调研：GitHub 初筛、README 摘要、资料整理，优先交给 Gemini 或低成本模型；Codex 只复核结论。
3. 2级简单修改：单文件、小脚本、明确文档更新，使用低推理强度。
4. 3级日常开发：多文件改动、测试、排错，使用中等模型和中等推理。
5. 4级高风险任务：安全、架构、复杂 bug、迁移、三次失败后的根因分析，才使用高档模型和高推理。

## 保存进度

- 日志必须完整，不做“轻量日志”。
- 日志草稿和重复性整理可以尝试交给 Gemini/低成本模型，但要先判断是否真的省额度。
- 如果调用其他模型需要传很多上下文、再由 Codex 大量复核，节省不明显，就由当前 Codex 直接写。
- 最终写入第二大脑、暂存、提交、推送必须由 Codex 复核路径、事实和敏感信息。

## 判断标准

- 能用 PowerShell、git、rg 等本地工具解决的，不升级模型。
- 只是收集资料或生成初稿，优先低成本模型。
- 涉及删除、凭据、账户、支付、架构、安全、跨仓库同步时，必须由 Codex 主模型决策。
- 用户说“低消耗执行”时，默认少解释、少调研、少读无关上下文，但验证不能省。
