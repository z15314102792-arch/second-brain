# 低消耗分级执行

## 核心结论

降低 Codex 额度消耗的关键不是少验证，而是把任务拆层：本地命令直接做，大范围调研初筛优先交给 Gemini，Gemini 不适合时再找免费/低成本模型，Codex 负责最终判断、危险操作、保存进度和复核。

日志不能降级。保存进度固定由当前 Codex 执行，不再每次判断是否交给 Gemini/低成本模型。原因是保存进度高度依赖当前对话上下文和真实操作记录，转交其他模型需要传上下文再复核，通常省不了多少，还增加漏事实风险。

WorkBuddy 不是默认“免费下级”。用户确认 WorkBuddy 也消耗积分，所以只有 Gemini 不适合、WorkBuddy 明显更顺手，或用户点名时才用它做前置材料。

Claude Code 曾接 DeepSeek-v4，实际体验还不错，但因涨价后性价比太低已放弃。以后不要再把“Claude Code 接 DeepSeek-v4”当当前推荐方案，只作为历史经验和排错背景。

## 执行规则

1. 0级本地命令：查状态、下载、解压、校验、启动、明确路径删除、`git status` 等，直接用本地命令，不额外调研。
2. 1级大范围调研：需要读取多个仓库、多个 README、长网页或大量资料时，优先交给 Gemini；Gemini 不适合时再找免费/低成本模型。WorkBuddy 因为消耗积分，不作为默认省钱方案；单点查询由当前 Codex 直接做。
3. 2级简单修改：单文件、小脚本、明确文档更新，使用低推理强度。
4. 3级日常开发：多文件改动、测试、排错，使用中等模型和中等推理。
5. 4级高风险任务：安全、架构、复杂 bug、迁移、三次失败后的根因分析，才使用高档模型和高推理。

## 保存进度

- 日志必须完整，不做“轻量日志”。
- 保存进度固定由当前 Codex 直接写，不交给 Gemini/低成本模型。
- 最终写入第二大脑、暂存、提交、推送必须由 Codex 复核路径、事实和敏感信息。

## 判断标准

- 能用 PowerShell、git、rg 等本地工具解决的，不升级模型。
- 大范围收集资料、GitHub 初筛、README 摘要，优先交给 Gemini。
- Gemini 不适合或不可用时，先找免费/低成本模型做简单任务；WorkBuddy 只在用户点名或确实更合适时使用。
- 禁止为了省额度调用 Codex 原生子 Agent；原生子 Agent 会并行消耗 GPT/Codex 额度。
- 涉及删除、凭据、账户、支付、架构、安全、跨仓库同步时，必须由 Codex 主模型决策。
- 用户说“低消耗执行”时，默认少解释、少调研、少读无关上下文，但验证不能省。

## 用户手动操作清单

用户只需要记自己的操作口令，不需要记模型内部流程：

- 想省额度：说“低消耗执行”。
- 换新任务：说“先总结 5 行，我开新会话继续”，再把总结贴到新会话。
- 问代码问题：尽量给具体文件路径、函数名、报错行。
- 给报错日志：只贴报错前后 30 行。
- 给长文档：先让 AI 看目录，再指定章节。
- 大范围调研：说“交给 Gemini 做初筛，Codex 最后复核”。
- Gemini 给出结果后：让 Codex “只检查有没有漏洞，不要重写全文”。
- AI 连续失败 2 次：说“停，先列假设和证据，不要继续改”。
- AI 连续失败 3 次：说“停止试错，给我 3 个方案选”。
- 涉及钱、账号、删除、发布：要求 AI “先说明影响范围，等我确认”。
- WorkBuddy：只有用户明确点名或办公文档场景再用，不默认用来省钱。
