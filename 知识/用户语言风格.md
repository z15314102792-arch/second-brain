# 用户语言风格

> **用途**：任何 AI（Claude Code 或其他）与本用户对话前，先读本文件 + [[知识/用户人物画像]]，快速理解用户怎么说话、怎么下指令、真实意图是什么。
> **配套档案**：[[知识/用户每日关注主题]]（每天关注什么）。
> **数据来源**：基于用户 2026-07-25 至 2026-08-16 的 1605 条真实消息统计分析得出。
> **更新规则**：语言习惯有显著变化时更新，升级版本号。

---

## 一、说话总特征

1. **口语化，像微信语音转文字**：语气词多（吗/吧/呢/啊），口语连接词多（就 455 次、就是 186、然后 123、而且 86）。
2. **短句命令式**：大量 2 字指令（去/改/执行/修复/检查/继续/下一步），431 条消息不超过 10 个字。
3. **一句话拆几条发**：常 30 秒内连发 2-4 条、逐条补充。AI 要把连发的几条**合并**看成一句完整的话。

---

## 二、高频指令词 → 真实含义对照

| 用户打的 | 真实含义 | 备注 |
|---------|---------|------|
| 继续 / 下一步 / 然后呢 | 上一步我做完了，你接着往下，别停 | 最高频 |
| 去 / 改 / 执行 / 动手 | 别问，直接做 | 要结果，不要解释 |
| 检查 / 检测 / 检索 / 调研 | 你自己查清楚再回我，别让我操作 | 要 AI 自主 |
| 保存进度 | 存档到第二大脑 + git 推送 | 常打错成「保持进度/保持距离/保持记录/报春进度」 |
| 你好 | 测试你在不在 / 切换模型后确认 | 常连发多条 |
| 算了 / 不用了 / 我解决了 | 停止这个方向，换或结束 | 用户自己搞定了 |

---

## 三、怎么表达需求（思维习惯）

- **结果导向**：要的是「目的达成」，不是某个具体手段。AI 别只盯字面要求，要追问或推断真实目的。
- **要最简方案**：步骤太多、太麻烦会直接拒绝。优先给「一步到位」的方案。
- **调研先行**：希望 AI 先查别人怎么解决的，别闭门造车、别臆想。
- **决策授权但有约束**：说「你自己决定」时，其实是在「我说清的范围」内让你定。没给约束就空甩决策 = 会被用户批「不切实际」。AI 应先补约束、再给方案。

## 四、语音输入同音错字对照（AI 要能识别，识别不了就反问）

| 用户打的 | 想说的 |
|---------|--------|
| 保持进度 / 保持距离 / 保持记录 / 报春进度 | 保存进度 |
| 温馨 | 微信 |
| 树妖 | 需要 |
| 鬼泣 / 贵器 | 过期 |
| 集体事件 | 具体时间 |
| 世界（如「多花世界」） | 时间 |
| 分案 | 方案 |
| 瞒住 | 满足 |
| 接触一下 | 结束一下 |
| 唉断句 | AI 断句 |
| 推倒 | 推送 |
| 一步话 | 一步化 |
| 必须行 | 必要性 |
| 产于 | 参与 |

> AI 遇到看不懂的词，优先用「你是不是想说 XX？」反问确认，不要直接按字面执行。

---

## 五、AI 该怎么和用户说话

- 简洁直接，少讲道理，给**具体可操作的第一步**
- 新概念 / 术语首次出现必须通俗解释（用户是小白）
- 别用「你应该」句式，给路径和反馈节点
- 做完给完整文件路径
- 主动提醒更优方案，但不确定的不说
