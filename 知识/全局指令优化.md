### 2026-08-06 约 18:00：Agent 分派标准重写（经过三轮迭代）

**第一版**："分派前先自己摸一把"。问题：每个任务都要先摸，拖慢节奏。

**第二版**："需要读文件才分派"。用户指出太绝对。讨论结论——对 LLM 来说，"绝对"有好处（歧义最小、矫正过偏），也有坏处（规则间会矛盾、穷举不到的场景会漏）。

**第三版（最终）** ：默认+例外模式——不需要读文件和做判断的纯信息收集自己直接做。例外：信息分散在多个不相干目录、或需要的命令超过 5 条时，可分派。

写入前走了自查三问：①能落地（和现有规则无冲突）②有更省的吗（合并到已有"任务执行"板块，不单开）③有副作用吗（有，但"不确定不说"刹车挡住噪声）。

### 2026-08-06 约 19:00：规则太绝对问题讨论

三条规则（调研先行、自测、版本标示）都用了"每次/必须/禁止"这类绝对词。对 LLM 来说，"每次"就是字面意思——改一个 typo 也要调研、改一行 CSS 也要五维度测试、改 CLAUDE.md 两行也要升版本号。

分析了三种写法对 LLM 的影响：
- 绝对用语：歧义最小，但触发范围太大
- 模糊用语：灵活但不能保证执行
- 默认+例外：既有清晰默认也有判断空间，对 LLM 最优

决定给三条规则加微小改动豁免。讨论过一个通用豁免方案（"大小有别"一条解三条），暂未写入，每条单独修更精准。

### 2026-08-06 约 20:00：中文 vs 混合格式

讨论了纯中文自然语言 vs 结构化格式（YAML 字段 / 决策树 / 正反例）对 LLM 执行精准度的影响。关键发现：Anthropic 的 prompt engineering 实践确认——结构化声明 + 正反例 + 自然语言说明三者组合，LLM 执行准确度最高。

**结论**：当前规则 < 20 条，纯中文足够。**格式不是瓶颈，规模才是。** 规则超过 25 条或出现互相矛盾时再考虑切换混合格式。

同场讨论：`###` 在 Markdown 里不是注释，是三级标题，LLM 会读取。CLAUDE.md 里没有任何"仅人类可见"的内容——整个文件原样塞进上下文。用户如需自己看备注，可另建 `CLAUDE-README.md`，但维护两份文件有成本。

### 2026-08-06 约 21:00："有更好的就说"（经过两轮优化）

**背景**：Claude 默认模式是问什么答什么。用户不主动问"有没有更好的做法"，Claude 不会说。但用户作为非技术人员，不可能知道自己不知道什么。

**第一版**：设三个触发点——选工具时、给方案时、教方法时。用户指出太繁琐："我只是正常发问，不是说不行"。

**第二版**：精简为一句——"回答完一个问题或做完推荐后，如果你知道更优的方案、工具或做法，简短提一句，问要不要展开。不确定或略微更好的不说。"不设触发点、不设检查清单、不给强制输出。刹车是"不确定的不说"，防噪声。

写入前走了自查三问确认无误。

### 2026-08-12：基于跨会话错误模式的规则可靠性优化

**触发**：会话 a0e9ca60 中集中爆发了 10 个错误（推荐不必要的软件、给不可用的链接、死磕错误方向、推荐未验证的操作路径、跳过调研、忘记已有配置、编造手机 UI 三次、推卸排查工作）。用户要求调研这些错误的根因并给出可落地的解决方案。

**调研**：搜索了 Claude Code GitHub Issues（[#44246](https://github.com/anthropics/claude-code/issues/44246)、[#19252](https://github.com/anthropics/claude-code/issues/19252)、[#80873](https://github.com/anthropics/claude-code/issues/80873) 等）+ 官方文档 + 社区实践。发现三层策略（精简 CLAUDE.md + Skills + Hooks）是社区共识的最优解。

**核心发现**：
- CLAUDE.md 规则本质是"建议"不是"约束"——架构设计如此，措辞更硬也不能提高合规率
- 指令衰减真实存在——规则在前 5-10 轮有效，之后逐渐被忽略
- 否定句式降低合规率（"粉红大象问题"）
- Skills 每轮被检索匹配，比 CLAUDE.md 只加载一次更可靠
- Hooks（exit code 2）是唯一可靠的强制执法机制

**落地的改动（v2.5）**：
1. CLAUDE.md：调研板块否定句改正向（"禁止跳过"→"第一个动作：搜索"）；新增网络操作前 Grep 记忆库规则；新增手机 UI 禁令；新增用户操作前自检索规则
2. 新建 3 个 Skill（调研先行、记忆检索、移动端指导），放入全局 `.claude/skills/` 和 memory 项目 `.claude/skills/`
3. 新建 Stop Hook（research-gate.py）：拦截"未调研就推荐方案"的完成声明

**关键认知**：CLAUDE.md 自然语言规则在 LLM 架构上不可靠是机制边界，不是规则写得不够好。三层策略（精简 CLAUDE.md + 高频规则迁 Skill + 关键拦截用 Hook）是当前最优解。详见 `日记/2026-08-12-进度.md`。

**v2.6 二次审查修复**：Hook 关键词 `方案` 和 `建议你` 太宽泛导致误匹配（「最终方案」「方案A」「建议你先备份」），替换为更精准的组合词（`推荐方案` / `建议你用` `建议你装` `建议你试试`）。同时记录了子 Agent 调研不可见、Stop Hook 事后触发两个架构限制。

**v2.7 三次审查补漏**：发现 8 个口语推荐变体未被捕获（装个、装一个、下这个、可以装等），新增 4 个关键词。验证了 Skill 间无冲突、全局/项目副本一致、5 类原始错误全覆盖。
