## 🐛 Claude Code 乱码修复（三重根因）

详见 [[项目/Claude Code 环境维护]]

### 问题现象
Claude Code 界面显示中文乱码。

### 根因（三重叠加）

| # | 根因 | 说明 |
|---|------|------|
| 1 | hook 命令 Linux 语法 | `PYTHONUTF8=1 python xxx.py` 是 bash 写法，Windows 的 Claude Code 用 PowerShell 执行，把 `PYTHONUTF8=1` 当命令名报错 |
| 2 | python 不在 PATH | 系统 `python` 是 0 字节商店占位别名，真 Python 在 workbuddy 目录 |
| 3 | Python 默认 GBK | 中文系统下 stdin/stdout/stderr 默认 GBK，与 Claude Code 的 UTF-8 不匹配 |

### 修复内容

1. **5 个 hook 脚本**在 import 后加 UTF-8 强制（`reconfigure(encoding="utf-8")`）：token-guard.py、verification-gate.py、research-gate-pretool.py、research-gate.py、research-tracker.py
2. **settings.json**：6 处 hook 命令的 `PYTHONUTF8=1 python` 前缀去掉，改用 workbuddy Python 绝对路径

### 验证结果

- settings.json 解析合法，无 `PYTHONUTF8` 残留，6 处命令全部绝对路径
- 5 个脚本 `py_compile` 通过
- subprocess 模拟 Claude Code（UTF-8 管道 + 中文输入）调用：正确拦截（exit 2），中文输出乱码替换符 0 个

## 🐋 DeepSeek Harness 转圈根治（Edge 92 → 151）

详见 [[项目/DeepSeek-Harness]]

### 问题现象
Web UI 永久卡在 loading 转圈，进不了主界面。

### 根因（纠正 v1.1 的误判）

1. 用户 Edge 版本 **92.0.902.67**（2021 年 9 月），过时约 5 年
2. dsh 前端用了 ES2022 的 `Object.hasOwn`（Edge 93+ 才支持），Edge 92 直接 `TypeError` → boot 崩溃 → 永久转圈
3. Edge 92 还有 WebSocket bug，实时下行连接失败

> ⚠️ v1.1 曾误判根因是 `127.0.0.1` 和 Edge `--app` 模式，已纠正。

### 修复（两条都做了）

1. **注入 polyfill**：编辑 index.html，加一行 `Object.hasOwn` polyfill（新浏览器条件为 false 自动跳过，向后兼容）
2. **升级 Edge 92 → 151**：自动更新三条路全部失败（更新器日志 `0x80040c01`），改下载微软官方离线包 `MicrosoftEdgeEnterpriseX64.msi`（203MB，数字签名 Valid），`msiexec /i ... /qn /norestart` 静默覆盖，**92.0.902.67 → 151.0.4129.86**

### 端到端验证（原始数据）

新版 Edge (151) headless + CDP 实测：

| 检测项 | 结果 |
|--------|------|
| boot 清单存在 | true |
| 仍显示转圈 | false |
| 主界面文字 | 探索未至之境 / 预览版 / 选择工作区 / 标准模式 |
| WebSocket 握手 | 101 Switching Protocols × 2 |
