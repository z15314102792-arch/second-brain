### 死锁根因（重要发现）

昨天备份被 token-guard 反复拦截，死锁无法自救。今天定位到根因：

**机制**：token-guard 用 `tool_calls_since_user` 计数，达到 50（VOLUME_CEILING）就 block 所有工具。而 goal 命令的自主循环（"循环执行直到自检通过"）在 Stop 时注入的反馈**不触发 UserPromptSubmit**，导致计数器永不重置，形成死锁。

**关键证据**：Stop hook 反馈和用户手动输入是两回事——只有真正的用户输入才触发 UserPromptSubmit 重置。goal 循环反馈 → 工具仍被 block → 又触发 Stop → 又注入反馈，无限循环。

**解锁方式**：用户手动发一条真正的消息（触发 UserPromptSubmit），计数器重置后恢复。

### 需要改动（待办）

- [x] token-guard 加只读工具逃生通道，避免 goal 循环死锁（✅ 已完成并验证，见下）
- [x] goal 命令加连续失败保护 → 结论：`/goal` 是内置命令改不了，官方无此参数，正确做法是条件里写 bound 子句（`或 20 轮后停止`），已写入 [[知识/goal命令]]（调研修正了之前"改代码"的错误方向）

## 🔍 卡点调研失效根因 + 任务规划方案调研（收尾，不落地代码）

本会话后半段的调研结论，已定案、不再落地代码（用户确认"不需要了"）。

### 核心结论：官方 Plan Mode 是最优解

针对"每次任务先分析需求、设定流程"的需求，调研发现 Claude Code 官方已内置 **Plan Mode**（计划模式），比自写 hook 更好：零额外 token、有审批环节（不批准不动手）、社区验证充分。用法：`/plan` 手动切，或 settings.json 设 `defaultMode: "plan"`。自写 task-briefing hook 是重复造轮子，已放弃。

### "卡点调研"为什么失效（根因，可复用）

- 纯文本规则（CLAUDE.md）是软约束，长会话注意力衰减
- "卡点"需要自我觉察，而卡点时恰恰不自觉
- 记忆冒充调研：issue 编号来自训练记忆，误以为"已经调研过"
- hook 注入的自然语言指令会衰减：Scott Spence 实测强制注入 ~84%（vs 基线 ~50%），但作者 2026-03 报告被 Claude 开始跳过；社区称 "harness debt"

### 技术天花板（重要认知）

hook 只能 ①允许/阻断工具 ②注入文字，**不能自己调用 WebSearch/WebFetch**。所以"强制去搜索"只能做到"阻断盲试 + 注入搜索指令"，最后"搜"这步是模型决策，无法硬保证。能强制"停"，不能强制"搜"。

### 关键参考

- Plan Mode：https://code.claude.com/docs/en/permission-modes
- Scott Spence 评测：https://scottspence.com/posts/measuring-claude-code-skill-activation-with-sandboxed-evals
