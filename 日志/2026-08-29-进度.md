## 鼠标滚轮部分场景失效修复

背景：

- 用户在豆包中排查了一个 Windows 鼠标滚轮异常：鼠标硬件本身正常，但在剪贴板历史（Win+V）、文件管理器等场景中，直接滚动滚轮无效，只能拖动右侧滚动条。
- 浏览器、桌面等其他场景滚轮正常，因此初步排除鼠标硬件故障。

排查过程：

- 确认系统为 Windows 11 专业版（Build 26200）。
- 检查鼠标滚轮相关注册表配置：
  - `HKCU\Control Panel\Desktop\MouseWheelRouting = 0`，异常。
  - `WheelScrollLines = 6`，正常。
- 检查第三方鼠标或手势增强软件，未发现罗技、手势工具等明显干扰项。
- 检查鼠标设备与驱动状态，设备无报错；额外发现 2 个腾讯虚拟 HID 鼠标设备（`MyAppsHidBus.sys`），但判断为次要可疑项，不作为本次主因。
- 核对 `MouseWheelRouting` 含义：`0` 表示禁用悬停滚动，`2` 表示启用 Windows 11 默认的悬停滚动行为。

根因：

- `MouseWheelRouting` 被改成 `0`，导致系统关闭“鼠标悬停在非活动窗口上时滚动该窗口”的功能。
- 剪贴板历史属于浮层窗口，不一定抢焦点；文件管理器在未获得焦点时也会受影响。滚轮事件被发给当前活动窗口，而不是鼠标指针所在窗口，所以出现“部分场景失效、换场景正常”的现象。

解决：

- 将注册表值改回：
  - `HKCU\Control Panel\Desktop\MouseWheelRouting = 2`
- 等效图形界面路径：
  - 设置 → 蓝牙和其他设备 → 鼠标 → 滚动 → 打开“将鼠标悬停在非活动窗口上时滚动它们”
- 用户实测：修改后鼠标滚轮恢复正常。

沉淀：

- 遇到“活动窗口可滚动、非活动窗口或浮层不可滚动”的 Windows 滚轮问题，优先检查悬停滚动设置和 `MouseWheelRouting`。
- 不要先判断为鼠标硬件坏；“换场景正常”通常说明硬件和基础驱动大概率可用。
- 腾讯虚拟 HID 鼠标设备可作为后续排查项，但本次问题已由悬停滚动设置恢复解决。
