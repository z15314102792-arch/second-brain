# AI日报 | 2026-09-25

## 1. AI 动态

### ★★★ [Claude 发现新型酶系统，带有类 CRISPR 重复序列](https://www.anthropic.com/news/claude-discovers-novel-enzyme-system)
- **发生了什么**：Anthropic 宣布 Claude 在生物信息学分析中发现了一种此前未知的酶系统，其特征是具有类似 CRISPR 的重复序列结构。这意味着 AI 不只是辅助检索文献，而是真正参与到了新生物学结构的识别工作中。CRISPR 本身是基因编辑的核心工具，任何与之相关的新发现都可能对基因工程领域产生连锁影响。
- **为什么重要**：这是 AI 从「工具」向「科研合作者」转变的一个标志性案例。如果 AI 能在海量序列数据中发现人类尚未注意到的模式，那它在材料科学、药物发现等数据密集型领域的价值会被重新评估。同时这也给 AI 公司提供了一个新的叙事方向：不只是降本增效，而是直接产出科学发现。
- **跟我有啥关系**：作为个人开发者，这件事本身不直接改变你的开发流程，但它说明「AI + 领域数据」的玩法正在被验证。如果你以后想做教育类或科普类小游戏，这类「AI 发现」的案例是很好的内容素材。
- **分析**：亮点在于这是可验证的科学发现，不是营销话术。潜在风险是这类发现的实际生物学意义还需要实验验证，目前只是计算层面的识别。值得跟进的是 Anthropic 是否会开放相关数据集或方法，如果开放，对做生物信息可视化的开发者是个机会。

### ★★★ [Google Project Suncatcher：把 ML 基础设施送上太空](https://blog.google/innovation-and-ai/models-and-research/google-research/google-project-suncatcher-facts/)
- **发生了什么**：Google 公布了 Project Suncatcher，计划将机器学习基础设施部署到太空。背景是地面数据中心的能耗、散热、土地和电力供应越来越成为瓶颈，而太空有近乎无限的太阳能和天然的低温散热环境。Google 此前在数据中心能效上投入巨大，这次是把思路从「优化地面」扩展到「换一个地方」。
- **为什么重要**：如果这条路走通，AI 算力的物理约束逻辑会被改写。短期内不现实，但它释放的信号是：大厂已经在为「算力需求继续指数增长」做极端预案。对芯片、能源、航天三个行业都是长期变量。
- **跟我有啥关系**：对你这种个人开发者来说，短期内没有任何直接影响。但如果未来云端推理成本因为算力供给方式变化而下降，小游戏里接入 AI 功能的门槛会进一步降低。
- **分析**：亮点是思路足够大胆，且 Google 有航天和 AI 双重积累。风险是工程难度和成本极高，很可能长期停留在「研究项目」阶段。值得跟进的不是技术本身，而是它反映出的行业焦虑：算力需求正在逼着大厂想非常规办法。

### ★★ [Mercury 2.5 LLM 达到每秒 770 tokens](https://artificialanalysis.ai/models/mercury-2-5)
- **发生了什么**：Mercury 2.5 在 Artificial Analysis 上的评测显示其推理速度达到 770 tokens/秒。这个速度远超目前主流大模型的输出速度，意味着在需要实时交互的场景中，延迟会大幅降低。高速推理一直是小模型或专用硬件的卖点，Mercury 系列走的是这条路线。
- **为什么重要**：速度是 AI 应用体验的关键瓶颈之一。770 tokens/秒意味着几乎可以做到「说完即出」，这对实时对话、游戏内 AI 角色、代码补全等场景意义很大。它也说明模型竞争不只在「谁更聪明」，还在「谁更快更便宜」。
- **跟我有啥关系**：如果你以后想在小游戏里嵌入 AI 对话或 AI 对手，推理速度直接决定体验流畅度。高速模型的出现让你可以用更低的成本做实时交互，而不是等好几秒才出结果。
- **分析**：亮点是速度指标确实有吸引力。风险是速度往往以模型能力为代价，需要看它在具体任务上的表现是否够用。值得跟进的是它的定价和 API 可用性，如果便宜且快，对独立开发者很友好。

### ★★ [微软 SkillOpt：面向 Agent 技能的训练循环](https://microsoft.github.io/SkillOpt/)
- **发生了什么**：微软发布了 SkillOpt，一个用于训练 Agent 技能的训练循环框架。当前 AI Agent 的痛点之一是「会聊天但不会做事」，SkillOpt 试图通过系统化的训练循环让 Agent 掌握具体技能，而不是依赖 prompt 工程硬凑。
- **为什么重要**：Agent 是今年 AI 应用的主战场，但大多数 Agent 在实际任务中表现不稳定。如果 SkillOpt 这类框架能降低训练 Agent 技能的门槛，会加速 Agent 从 demo 走向可用产品。
- **跟我有啥关系**：如果你以后想给小游戏加一个「能自己玩」的 AI 对手，或者做一个自动化测试 Agent，这类框架值得关注。它可能让你不用从零搭训练流程。
- **分析**：亮点是微软在 Agent 基础设施上的持续投入，开源框架对个人开发者友好。风险是这类框架往往依赖特定云服务或模型，实际使用可能有隐性成本。值得跟进的是它是否支持本地模型。

## 2. 日志

### 昨天做了什么

- 排查并修复了 Codex 桌面版新建「工作」任务时无法切换模型和推理强度的问题。现象是模型固定在 GPT-6 Astra、推理强度固定在高，切换时报「无法更新模型设置」。
- 通过本机桌面日志定位到切换请求后 `config/batchWrite` 失败，具体是无法将设置持久化到 `C:\Users\Administrator\.codex\config.toml`。
- 确认当前默认配置确实是 Astra、高，且文件可正常读取、TOML 可解析，说明不是配置格式问题。
- 找到根因：2026-09-17 启动的一个旧 Desktop Commander Node.js 子进程占用了 `config.toml`，Windows 下文件替换测试返回拒绝访问。
- 执行修复：先备份配置，然后只结束那个占用文件的旧子进程，没有动 Desktop Commander remote 服务本身。
- 验证修复：通过应用配置接口实际改值和恢复都成功；用户在新建「工作」任务页确认模型和推理强度均可切换，桌面日志显示写入成功。
- 最终默认值设为用户选定的 `gpt-6-sol`、`xhigh`。
- 写了知识文件：[[资料/Codex桌面版模型切换故障]]，把这次排查过程和根因记录下来。
- 代码提交：`1f13d77 确认并修复 Codex 模型切换文件占用`。
- 项目运行状态：中国象棋正常、五子棋正常、你画我猜正常、动物大战正常、螺丝消除正常、星月神殿 404 页面缺失。

### 遇到的问题和卡点

- 卡点一：现象是「无法更新模型设置」，但错误信息没有直接指向文件占用，需要从桌面日志里翻 `config/batchWrite` 的失败记录才能定位。
- 卡点二：`config.toml` 可读、TOML 可解析，表面看文件没问题，容易误判为应用 bug 而不是环境问题。
- 卡点三：占用文件的是一个 9 月 17 日启动的旧子进程，时间上离当天较远，不容易第一时间联想到它。

### 怎么突破的

- 从日志入手，找到 `config/batchWrite` 失败这条具体记录，把问题从「模型切换不了」缩小到「配置写不进去」。
- 用 Windows 文件替换测试验证文件是否被占用，返回拒绝访问，确认是占用问题而非权限或格式问题。
- 顺着进程来源追到 Desktop Commander remote 服务派生的旧 Node.js 子进程，只结束占用文件的那一个，避免影响其他服务。
- 修复前先备份配置，修复后通过应用接口实际改值和恢复做双重验证，再到 UI 层确认，形成完整闭环。

- 这次排查花了不少时间在「文件明明能读为什么写不进去」上。建议以后遇到配置写入失败，第一步就做文件占用检测，而不是先怀疑配置内容或应用逻辑。
