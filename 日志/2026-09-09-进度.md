### 痛点根因分析

用户反馈看板出现“已经重置了但是又没重置”的体感，经深度代码排查定位三大根因：
1. **微型能量条映射错位**：极简微卡片模式下，底部的微型能量条此前绑定的是周度配额（如 84%），而非用户高频关注的 5小时滚动配额。导致 5h 耗尽时进度条依然是满格绿色，5h 重置瞬间进度条毫无动态变化。
2. **到期重置未即时联动数值**：本地秒级定时器在倒计时归零（diff <= 0）时，仅在文字上输出 (已重置)，但缓存中的数值仍保留旧值（如 0%），造成 5h: 0% (已重置) 的视觉矛盾。
3. **缺少重置瞬间的主动刷新驱动**：到期瞬间未能主动向官方发起数据拉取，若服务端的 resetsAt 存在短时缓存延迟，过时时间戳未被自动纠偏。

### 本次完成

1. **能量条精准映射 5h 核心水位**：
   - 极简微卡片模式中的 mini_cd_bar、mini_gm_bar、mini_cg_bar 全量改回绑定 **5 小时限额水位**（cd_p5、gm_p5、cg_p5）；
   - 能量条与 5h 消耗、耗尽（归零变红）及重置（回满变绿）实现 100% 像素级即时同步。

   - _schedule_local_timer() 每一秒定时器在检测到倒计时 <= 0 瞬间，立即将数值与能量条修正回 100% 绿色状态，彻底消除 0% (已重置) 矛盾。
3. **重置时刻自动后台全量刷新**：
   - 到期重置瞬间自动在后台线程拉取最新官方配额与下一个周期的未来重置时间戳。

## AI 额度实时监控看板 v2.5 & v2.6 升级（消灭假死死锁 + 双引擎并发 + 全模型瞬显）

### 1. 痛点与卡点根因复盘
1. **死锁导致卡在“计算中...”**：
   - 原版 `query_codex_live_quota()` 对 `codex.exe app-server` 的标准输出进行了无超时的 `proc.stdout.readline()` 循环读取。在服务端输出完第 3 行后无更多内容时，第 4 行导致 Python I/O 线程**无限同步阻塞死锁**；
   - 原刷新逻辑将 Codex 本地查询与 Antigravity 网络查询串行串联，导致任意一方受阻，整个界面永远停滞在「⏳ 计算中...」。
2. **Gemini 数据缺失根因**：
   - 之前将 `query_antigravity_usage_quota()` 超时压缩至 8 秒，而 Windows 冷启动下 `agy.exe -p /usage` 耗时约 9~12 秒，导致每次查询均超时被强制掐断；且未配置专用持久化缓存。

### 2. 关键架构重构与突破
1. **I/O 线程化与 3 秒硬超时保护**：
   - `query_codex_live_quota()` 引入专用 I/O 线程与带 3.0s 超时的非阻塞队列机制，超时必杀子进程，彻底消除无数据死锁；
2. **双引擎完全独立异步并发（Codex 0.2s 瞬发上屏）**：
   - 重构 `refresh_all_data()`：Codex 本地数据 0.2 秒独立上屏显示，Antigravity 网络查询独立并发，两者互不干扰、互不阻塞；
3. **模型名称 0ms 本地瞬发直读**：
   - `query_antigravity_current_model()` 优先直接读取本地 `~/.gemini/antigravity-cli/settings.json`，耗时由 1.5s 降至 0ms；
4. **Antigravity 超时保护与持久化缓存（0ms 瞬显）**：
   - 建立 `ag_quota_cache.json` 本地持久化缓存，启动第一毫秒立即渲染真实配额（Gemini 5h 剩余 89% / 周度 96%，Claude 5h 剩余 100% / 周度 100%）与精准倒计时；
   - 放宽查询超时至 25 秒，后台静默拉取并平滑更新；
5. **全维度自动化验收测试通过**：
   - API 连通性、边界倒计时与归零纠偏、严格三色阶（>40%绿/15%~40%橙/<15%红）、模型名净化、静默无黑框等 5 个维度全部测试通过（ALL PASS）。

## AI 额度实时监控看板 v2.7 升级（彻底消灭 Codex 频繁断连与计算中闪烁）

### 1. 痛点与卡点根因复盘
用户反馈：“codex的一直重新链接是什么原因，也就是过会就会显示未连接，计算中等”。
经使用 `benchmark_codex.py` 与 `trace_codex_time.py` 追踪定位两大真凶：
1. **未注入代理环境导致直连被墙超时**：`codex app-server` 在执行 `account/rateLimits/read` 时内部向 `https://chatgpt.com/backend-api/wham/usage` 发起 HTTP 请求。由于过去未给子进程传递代理环境变量（`HTTP_PROXY` 7897 端口），在国内网络环境下直接被墙，直连等待 7.5 秒后报错 `error sending request for url`；
2. **读写线程对 error 响应遗漏 break 导致死等超时**：当服务端返回 `-32603` 错误时，`_reader_thread` 没有及时退出，而是在无新行时进入无限阻塞，死等到超时被杀；
3. **缺乏持久化缓存与平滑防抖降级**：过去只要单次后台 30 秒轮询因网络超时失败，就直接返回 `connected=False`、`5h_reset="计算中..."`，把正在正常倒计时的界面覆盖刷掉，造成断连闪烁。

### 2. 关键架构重构与优化
1. **为 Codex 子进程注入代理环境变量**：注入 `env=gemini_query_env()`，使 `codex.exe` 直连代理端口 7897，实测响应耗时由 7.5 秒超时骤降至 **1.3~2.0 秒秒级直达**！
2. **读写线程即时响应与合理超时**：`_reader_thread` 只要接收到 `id: 2` 响应（不论 result 还是 error）立刻 break 退出，彻底消除死锁和死等；
3. **双持久化缓存与平滑防抖降级（绝不闪烁）**：
   - 建立 `cd_quota_cache.json` 本地持久化缓存，启动 0 毫秒首屏直接呈现；
   - `_task_codex` 后台刷新若遇到网络偶发波动，**坚决不使用未连接数据覆盖有效界面**，平滑保留当前有效数据并继续本地秒级平滑倒计时；
4. **压测验证 100% 成功率**：连续 5 次连续高频压测，成功率 100%，平均响应仅 2.0s，彻底消灭断连与计算中闪烁。

### 3. 版本固化与部署
- 生产文件：`C:\Tools\AIUsageMonitor\AI_Quota_Monitor_ZH.pyw`（版本 `v2.7`，后台稳定常驻）
- 缓存文件：`cd_quota_cache.json`、`ag_quota_cache.json`
