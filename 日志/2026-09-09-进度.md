# 2026-09-09 进度

## AI 额度实时监控看板 v2.4 修复重置假死与能量条联动

### 痛点根因分析

用户反馈看板出现“已经重置了但是又没重置”的体感，经深度代码排查定位三大根因：
1. **微型能量条映射错位**：极简微卡片模式下，底部的微型能量条此前绑定的是周度配额（如 84%），而非用户高频关注的 5小时滚动配额。导致 5h 耗尽时进度条依然是满格绿色，5h 重置瞬间进度条毫无动态变化。
2. **到期重置未即时联动数值**：本地秒级定时器在倒计时归零（diff <= 0）时，仅在文字上输出 (已重置)，但缓存中的数值仍保留旧值（如 0%），造成 5h: 0% (已重置) 的视觉矛盾。
3. **缺少重置瞬间的主动刷新驱动**：到期瞬间未能主动向官方发起数据拉取，若服务端的 resetsAt 存在短时缓存延迟，过时时间戳未被自动纠偏。

### 本次完成

1. **能量条精准映射 5h 核心水位**：
   - 极简微卡片模式中的 mini_cd_bar、mini_gm_bar、mini_cg_bar 全量改回绑定 **5 小时限额水位**（cd_p5、gm_p5、cg_p5）；
   - 能量条与 5h 消耗、耗尽（归零变红）及重置（回满变绿）实现 100% 像素级即时同步。
2. **到期即时状态修正与纠偏**：
   - query_codex_live_quota() 与 parse_usage_text() 在解析时增加 resetsAt <= now 判定，时间戳到期自动修正为 100% 满额；
   - _schedule_local_timer() 每一秒定时器在检测到倒计时 <= 0 瞬间，立即将数值与能量条修正回 100% 绿色状态，彻底消除 0% (已重置) 矛盾。
3. **重置时刻自动后台全量刷新**：
   - 到期重置瞬间自动在后台线程拉取最新官方配额与下一个周期的未来重置时间戳。
4. **版本发布与部署**：
   - 版本升级至 **v2.4**，重新编译无报错，并已在后台平稳拉起运行。
   - 项目仓库 E:\项目\ai-quota-monitor 已完成提交并固化 v2.4 标签。
