## AI日报 v2.3：跨仓库 git log 修复

### 问题

用户反馈：AI日报的「项目健康」和「昨日动态」永远显示"无变动"，明明前一天做了大量动物大战改动（v3.4-v4.0）。

### 根因

Workflow 只 checkout 了 `second-brain`（memory）仓库，`git log` 只看到 memory 仓库的提交。但游戏代码在各自独立仓库（`animal-battle`、`chinese-chess`、`gomoku`、`draw-and-guess`）里，workflow 完全看不到。

### 解决过程

1. **方案 A（GitHub API + Python）**：用 `curl` 调 GitHub API 拉 commit，Python 解析 JSON
   - 失败原因：多行 Python 代码在 YAML `|` 块标量中缩进不正确（tab vs space），导致 YAML 解析失败，workflow_dispatch 触发器不被识别
   
2. **方案 B（heredoc）**：`cat > /tmp/script.py << 'PYEOF'`
   - 失败原因：heredoc 内容使用 tab 缩进，与 YAML 块标量的 space 缩进冲突
   
3. **方案 C（git clone --depth 5）✅ 最终方案**：
   ```bash
   for repo in chinese-chess gomoku draw-and-guess animal-battle star-moon-temple; do
     git clone --depth 5 "https://github.com/z15314102792-arch/$repo.git" "/tmp/repo_$repo" 2>/dev/null && \
       git -C "/tmp/repo_$repo" log --since="30 hours ago" --format="%h %ad %s" --date=short >> /tmp/git_log.txt
   done
   ```
   - 纯 shell + git 命令，零 Python 解析
   - 不依赖任何 API 或外部工具

4. **额外修复**：`daily_analyze.py` 第 128-129 行缩进错误（sed 插入时产生了双 tab）

### 🔐 SSH 密钥泄露应急处理 + GitHub 被墙永久修复

用户在 VS Code 操作时不慎选中了 `id_ed25519` 私钥文件，内容被系统自动带入对话上下文，私钥已暴露。

**密钥处理**：
1. 删除旧私钥，重新生成新密钥对
2. 新公钥：`ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIHFLfWpkxxwWXYrtSYvUl14yFAWPBKoqTInf7CgbE072`
3. GitHub 上旧公钥因网络被墙暂未删除，但旧私钥已不存在，旧公钥无效
4. 尝试用 `gh` CLI 删除旧公钥 → 失败（GitHub API 也被墙）

**GitHub 被墙永久修复**（用户问「为什么经常被墙，怎么解决」）：

根因：GFW 干扰 `github.com:443`（HTTPS）和 `github.com:22`（SSH），时好时坏。只有 `ssh.github.com:443` 稳定不墙——SSH 流量走 HTTPS 端口，GFW 以为是普通网页浏览，不拦。

最终配置 `C:\Users\Administrator\.ssh\config`：
```
Host github.com
    HostName ssh.github.com
    Port 443
    User git
    IdentityFile ~/.ssh/id_ed25519
    IdentitiesOnly yes
```

核心改进（相比旧版知识库记录）：
- 旧版用 `Host ssh.github.com` 单独定义 → 需要 `insteadOf` 改写所有 remote URL → 容易出错
- 新版用 `Host github.com` 直接指向 `ssh.github.com:443` → remote 保持 `git@github.com:...` 格式不动 → 零改写、新仓库直接 clone 就通
- 验证：`ssh -T git@github.com` 返回 "successfully authenticated" ✅，`git push --dry-run` 成功 ✅

**教训——为什么以前反复被墙**：
之前的知识 `[[知识/GitHub国内访问]]` 记录了方案但没有落地成永久配置。HTTPS 时好时坏，被墙了就临时切 SSH→又被墙了切 HTTPS→轮着来。这次直接把 SSH config 做到「github.com 就是 ssh.github.com:443」，不需要切来切去。

### AI日报 v2.7：DATE 时区修复（UTC→北京时间）

用户 8/12 发现今天的 AI 日报没有推送。

**根因**：GitHub Actions 定时在 UTC 19:00（北京 03:00）运行。`DATE=$(date +%Y-%m-%d)` 取的是 UTC 日期，还停留在前一天。防重复检查看到前一天的文件已存在就跳过了。结果：**自动推送永远不会生成北京当天日期的日报。**

**修复**（`daily-brief.yml` 两行）：
```bash
# 旧
DATE=$(date +%Y-%m-%d)
YESTERDAY=$(date -d "yesterday" +%Y-%m-%d ...)

# 新
DATE=$(TZ='Asia/Shanghai' date +%Y-%m-%d)
YESTERDAY=$(TZ='Asia/Shanghai' date -d "yesterday" +%Y-%m-%d ...)
```
commit message 里的 `date` 也同步改为北京时间。

**验证**：手动触发 workflow → 成功生成 `日记/2026-08-12-AI日报.md` ✅

**文件**：`.github/workflows/daily-brief.yml`
